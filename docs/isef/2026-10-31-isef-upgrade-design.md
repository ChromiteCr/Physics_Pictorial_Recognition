## 1. 一句话，和为什么选它

**一句话**：学生的"失败"实验，常常是把一个稍有不同的实验测得很准。实验侦探完全离线运行，它找出最能解释这组力学数据的隐藏原因（比如摩擦没平衡、弹簧秤竖着调零却横着用）；数据分不清时它直说分不清，并指出能把这些原因分开的那一次测量。背后的贝叶斯物理引擎同时充当"老师"：不用任何人工标注，也不用 API 标注，就能训练一个 4B 的视觉语言模型。项目要测的是：这种能力能迁移到多少训练中没见过的实验上。

**为什么选它**
- 老师要求"在大模型上动刀"。这里模型权重确实会改变（LoRA 微调），而且有对照实验证明，改变来自物理引擎的标注，不是模型学会了输出格式。
- 科学问题直接长在教学系统里。现在的 app 只会说"相对误差 < 15% 就算验证成功"；新系统回答课程标准要求的"分析误差来源，提出减小误差的方法"。
- "实践"和"闭环"靠你本人在真实器材上故意注入故障来完成。这条路不涉及人类参与者，不需要 IRB。
- 四个独立方案由三位立场不同的评审打分（ISEF 评委、可行性、物理教师），三位都选了这个方向，总分分别是 57.0、57.5、56.5，其余方案在 45 到 56 之间。之后一位反方评审挑出 3 个致命问题、18 个重要问题和 14 个次要问题，本文都已处理（见 §13）。

## 2. 目标、非目标、反目标

**目标**
1. 技术升级落在模型上：用引擎监督微调 Qwen3.5-4B，再和未微调的 4B、你的 Qwen3.8-27B、主流 API 模型比较。各方用同一份提示、同样的工具、同一种输出格式。
2. 科学问题和教学系统高度相关，并且有可证伪的主张、对照组和统计检验。
3. 产品要创新、有趣、科学：嫌疑人看板、"幽灵曲线"、测量前先给出各原因的预测、修正之后再复测验证。
4. 能识别任何实验：先用规则，规则不够时用本地视觉语言模型兜底，再问一个澄清问题，最后还有"其他实验"通道。手动选择六个课内实验在任何页面都一键可达，系统永远不会覆盖你的选择。
5. 系统内部不调用任何外部 API（删掉 explain_api.py 里的 GLM）。API 模型只在实验里当对照组。
6. 11/9 左右产品 v1 可用，11/14 全部交付。

**非目标**（11 月不做，写进计划的后续阶段）

- 视觉侧微调、9B、27B 微调、视频输入。
- 识别准确率的正式评估。图片来源未清，样本又太集中（见 §7 的 E7）。
- 展位的"评委挑战"游戏和教师端协议视图。放在 Phase 2，赶在附属赛冻结项目之前做完。

## 4. 科学问题和要检验的主张

（下面是想法层面的表述，计划里的版本要你自己写。）

**研究问题（草案）**：学生的力学实验数据偏离理论时，一个完全离线的系统能在多大程度上找出背后的系统误差来源，并选出最能区分各个候选原因的下一次测量？只用物理引擎标注的数据训练出来的小型视觉语言模型，能把这种能力迁移到训练中没出现过的实验上吗？

### 主线 A：可辨识性图谱（预先规定的定量成果，不当作假设检验）
- 对每个实验的每种测量方案，用模拟算出贝叶斯最优的混淆矩阵。方案包括：单次读数、课本标准的多点方案、标准方案加 1 次或 2 次 EIG 推荐测量；对照方案是加 1 次重复测量、加 1 次随机测量。混淆矩阵回答两件事：哪些原因在标准方案下根本分不开，分开它们需要哪一次测量。
- 每对原因的目标样本量是 2,000 例以上（最终按 11/3 实测的计算速度定）。只有置信区间上界低于你定的阈值时，才判为"混淆"。故障大小的先验和噪声各做 ×0.5、×2 的敏感性分析。
- 实证检验改成"预测效度"：在你的真实测量（E5）里，只用标准方案时，引擎在预测会混淆的那对原因上的混淆程度，是否落在图谱给出的区间内。
- 白板上可以推的例子：在胡克定律里，漏算挂钩质量、刻度尺零点偏移、记录弹簧总长而不是伸长量，这三种原因在斜率自由时都表现为 F–x 直线有截距，单靠标准数据分不开。称一下挂钩、读一下空载长度，就能把它们分开。

### 主线 B：闭环里的下一次测量（确认性假设）
- 假设：按期望信息增益（EIG）自适应地选下一次测量，比"最佳固定追加测量"更能提高真实原因的后验概率。"最佳固定追加测量"是指在独立校准集上平均效果最好的那一项固定测量，是最强的非自适应基线。课本上的扩展方案也会单独报告。
- 模拟检验放在"高保真错配世界"里做，用配对 Wilcoxon 检验。这个世界包含引擎从不建模的效应：滑轮惯量、空气阻力、绳子质量、偏态的计时噪声、偶发的抄写错误。
- 真实检验用你本人的故障注入实验。每次实验都把三种追加测量做一遍：EIG 推荐的测量、最佳固定测量（和 EIG 推荐不同时才做）、一次简单重复，顺序按预先提交的随机表。涉及混淆原因对的实验单独报告。
- "学生通常只会重复测量"这一点，在你找到并读过相关文献之前，只能算假设。

### 主线 C：模型升级和迁移（确认性假设，主要的机器学习主张）
- 假设：只用引擎标签微调的 4B（下称 S1）在留出实验上识别原因的表现，优于"打乱标签对照"。打乱标签对照用同样的提示和步数训练，只是原因标签被随机打乱。这个比较排除了"只是学会了 JSON 格式"这种解释。S1 相对未微调 4B（3-shot）的提升作为总效应报告。
- 用双侧检验。计划里要写明：已有工作预测 SFT 的迁移可能失败（Chu 等 2025，"SFT 记忆、RL 泛化"，检索线索），所以零结果或负结果同样有意义，会如实报告。
- 指标是"等价类"上的 top-1：图谱判定为完全混淆的原因合并成一类。也可以只在可辨识的子集上算 top-1。同时报告全部样本的 log score 和 Brier 分数。
- 统计单位：结论只说"在这 N 个留出实验上"。逐个实验报告结果，并做跨实验的精确符号检验。只有 6 个实验时，必须 6 个全部提升才能得到 p < 0.05，所以建议再加 2 到 4 个便宜的留出实验（见 §5.1）。
- 次要分析（用 Holm 校正）：
  - 迁移阶梯：同分布 → 噪声偏移 → 留出原因 → 高保真世界 → 近迁移和远迁移实验
  - EIG 遗憾值
  - 校准（Brier、ECE）
  - 干净数据上的误报率
  - 解释的忠实度
  - 和 27B 的比较（只给估计值和置信区间，不做非劣效声明）
  - 和 API 模型的比较
  - 去掉特征面板的消融
  - 开启思考的未微调 4B（约 4k token），回答"微调是不是只换来了速度"

### 解读任何结果之前，这些对照必须先通过
- **K0**：训练时的格式和 Mac 上的服务路径，对 20 个提示生成的 token ID 必须完全一致。
- **K1**：把正确答案直接放进提示，准确率应接近满分。这证明评测流水线和解析器没坏。
- **K2**：泄漏检查器能抓到故意放进去的重复样本。
- **K3** 换表对照：每个样本保留原标签，但数据表换成同一实验另一个样本的。所有模型都应降到机会水平，机会水平定义为两个边际分布的乘积。样本量 n ≥ 600，用等价区间判断。
- **K4** 适配器效应检查：转换到 Mac 上的适配器确实改变了模型输出。
- **K5**：去掉特征面板的消融。
- **K6**：在模型内的数据上，引擎是校准良好的（ECE 约为 0）。这一步顺带检查网格积分有没有写错。

### 升级不该改变的东西
- 通用物理题：PhyX（MIT 许可）至少 1,500 题，在服务器上做等价检验（TOST）。反方算过，300 题的统计功效不够。
- 照片识别：11 月只做描述性比较，正式的等价检验放到 Phase 2。

### 工程指标（通过或不通过）

- **EC2**：产品峰值内存的阈值，按开发阶段的实测值在 E8 之前定好；所有同时运行的进程合计不超过 24 GB，以看门狗日志为准。

## 5. 技术组件

### 5.1 labsim：12 个力学实验的可执行物理孪生（P0）
- 用 numpy 写的前向模型，模拟测量过程和仪器噪声。
- **训练实验**（app 里已有的 6 个）：摩擦力、平均速度、胡克定律、牛顿第二定律（悬挂重物）、动量守恒（两辆小车）、机械能守恒。
- **留出实验**只用来评分，从不进入训练，并且事先分好类：
  - 近迁移：斜面摩擦、阿特伍德机、自由落体
  - 远迁移：单摆测 g、平抛、杠杆平衡

  如果你还能多审几张物理卡，再加 2 到 4 个：弹簧振子周期、浮力、打点计时器测 g。
- **程序化任务族**（反方提议新增，放进训练池）：随机的线性化定律、随机命名的变量、通用的故障算子（偏移、比例、弯曲、散布、漂移），并用多样的物理语言描述。这样模型是从几百种"描述 → 特征"映射里学，而不是只从三十来种里死记。留出实验的原因描述由 GPT 或你独立撰写，泄漏检查器检查两者之间的 n-gram 重叠。
- 每个实验有 4 到 6 个原因，其中一定包括"只有随机误差"。每个原因带四样东西：通俗描述、机制标签、修正方法、来源标签（"文献"或"假设"）。
- **机械能实验**按你 app 里的实际方案（小车加轨道，输入质量、高度、末速度）重写原因：
  - 遮光片宽度误差
  - 把斜面长度当成高度（只在没记录角度时才成立）
  - 滚动摩擦
  - 车轮的转动惯量。车轮占总质量 10% 时，约损失 5% 的平动动能，比钢球滚动时损失的 2/7 小得多。

  只有学校真有钢球和导轨，才加入钢球模型。
- 每个训练实验扣下一个原因不参与训练，用来构成"已知实验里的新原因"这一级测试。
- 噪声尽量用文献值，比如手动计时误差、分辨率 d/√12、刻度尺 ±1 mm。没有文献值的（弹簧秤竖放和横放的零点漂移、视差）用宽先验，标为"假设"，并纳入敏感性分析。计时误差的文献值来自受过训练的计时员，要注明这一点，并靠 ×2 的噪声敏感性分析覆盖学生的情况。
- 每个原因自动生成一页物理卡（公式、特征推导、来源标签），给你审核。

### 5.2 贝叶斯诊断引擎，会诚实地说"不在我的清单里"（P0）
- 计算 {只有随机误差、原因 1 到 K、以上都不是} 的后验概率。故障对参数是线性时用闭式边际似然，否则用网格积分。弹簧真实劲度、真实摩擦系数、g 这类干扰参数在网格上边际化掉。
- 后验预测失配统计量按模拟结果校准到固定的误报率，超过时触发"原因不在我的清单里"。
- z 一致性 = (测量值 − 预测值) / 合成标准不确定度。只有在数据有 3 个以上点（有 A 类不确定度估计），或者有文献噪声项时，才单独显示 z 色带；否则和嫌疑人看板的解释放在一起显示。这样可以避免只有一个读数时几乎总显示"不一致"。
- 引擎输出一份事实单：数字、单位、方向、主要原因、幽灵曲线、修正方法和复测的预测值。解释器、校验器和界面共用这份事实单。
- 注册表 v2：把 physics.py 的单次读数表单改成多点表格加仪器配置，单次读数仍然可以输入。

### 5.3 EIG 测量顾问和闭环（P0）
- 对每一项可行的追加测量，用蒙特卡洛方法计算 EIG（可以按每分钟实验时间归一化）。顾问推荐最好的一项，说明它能分开哪些嫌疑人，并在学生动手之前给出每个嫌疑人对应的预测结果。最多 3 轮。如果菜单里没有任何测量能分开剩下的嫌疑人，就直接说明。
- 后验更新在一整批模拟结果上向量化计算。11/3 先在调试规模上计时，再按实测速度定每格样本量。训练标签所需的 EIG 在服务器 CPU 上计算，和 GPU 训练同时进行。
- 识别环节的那个澄清问题，也由同一套代码来挑选。

### 5.4 特征面板和封闭的特征词表（P0，用来拉平各组的工具）
- 给定任意一张实验卡（线性化的定律、变量、单位、仪器分辨率）和一张数据表，代码计算以下面板量：
  - 自由比例拟合的斜率比及其 z
  - 截距的 z
  - 曲率的 z
  - 残差散布相对于仪器噪声是偏大还是偏小（χ²/dof）
  - 按试次顺序做的游程检验和漂移
  - 守恒类实验中前后比值及其不确定度
- 数据特征只用可观测的面板量：截距、斜率比、曲率、散布偏大、散布偏小、漂移。"x 偏移"和"y 偏移"只作为原因的机制标签，因为定律是直线、斜率又自由时，这两种偏移属于同一族函数，无法区分。
- 所有对比组（未微调模型、微调模型、27B、API、经典方法）拿到完全相同的面板，所以提升不可能来自"模型学会了算术"。

### 5.7 评测框架（P0）
- **冻结测试集**只在 Mac 上生成一次，由你启动。哈希之后上传（压缩后约 2 MB），服务器上再核对哈希。读数按仪器分辨率取整，两台机器固定同一个 numpy 版本。服务器只负责生成训练池。
- **提示契约**由所有对比组共用：同样的实验卡、候选原因、面板和 schema，贪心解码，每组至少 1,024 个新 token，逐组报告截断率和非法输出率。本地模型关闭思考；API 模型用最低的推理档位，并记录下来。
- **非 LLM 参考组**：在面板特征上训练的梯度提升树，以及一个 20 行的规则匹配器。两者都会拿到正确的原因特征标签，用来回答"到底需不需要语言模型"。
- **三个参照**分开定义：贝叶斯参照（用生成器先验的引擎）、参数神谕（理论上界）、错配引擎（高保真世界里的引擎）。归一化公式写进计划：(acc − chance) / (Bayes − chance)。
- **统计方法**：精确 McNemar 检验、Wilcoxon 符号秩检验、Wilson 区间和 Clopper-Pearson 区间、配对 bootstrap、TOST、Holm 校正、Brier、ECE、AUROC。跨实验的泛化用精确符号检验，不用只有 6 个簇的 bootstrap 当泛化区间。
- **日志**：所有本地和 API 的提示与回复都存成 JSONL，包括模型、版本、设置和时间，作为 Form 2A 的附件。
- **正式运行启动器**：只有你能启动正式运行。启动器会要你输入名字，自动在实验记录本里写一条带日期的记录；如果计划的哈希缺失，就拒绝运行。

### 5.8 事实单解释器、声明校验器和脚本模式（P0）
- 课内实验：本地模型只根据引擎的事实单写不超过 120 字的解释。"其他实验"：根据模型自己输出的 JSON 写，并标注"AI 估计，未经物理验证"。
- 规则校验器（支持中英文）抽出解释里的每个数字和单位、方向词（偏大、偏小）、原因名称和推荐测量，逐一和事实单核对。它还要求解释覆盖三项内容：主要原因、一个数值证据、下一次测量，防止空话过关。模型可以改写一次，还不通过就换成固定模板。
- 脚本模式只用模板，不出现任何生成文本，是默认模式。

### 5.11 真实故障注入实验（P0，只由你本人操作）
- 规模：3 个实验 × 4 种条件（干净，加 3 种故障）× 2 次重复 = 24 次。
- 推荐的 3 个实验：
  - 胡克定律
  - 摩擦力或牛顿第二定律，看学校有什么器材
  - 一个留出实验：单摆，走"其他实验"通道。可注入的故障有：摆长量到摆球顶端（x 偏移）、大振幅（弯曲）、数错全振动次数（斜率比例）。用手机传感器计时（例如 phyphox），这样不涉及人的反应时间。

  单摆这一组专门检验产品里真正部署给学生的那项能力，并配一个不用 LLM 的基线（从数据特征映射到一份通用的嫌疑原因清单）。
- 每个实验至少包含一对图谱预测会混淆的原因。
- 故障尽量由在场负责安全监督的成年人按密封卡设置，适合那些一眼看不出来的故障：弹簧秤零点、贴错标签的钩码质量、遮光片宽度的录入。这一步要作为成人操作步骤写进计划，不记录关于这位成年人的任何数据，并在 Form 2A 里列出这项帮助。由你自己设置的故障标为"未盲"，作为局限性写明。
- 数据先录入 CSV 并哈希冻结，之后才交给软件。
- 不在真实弹簧上做"超过弹性限度"的故障，它会损坏弹簧，甚至让弹簧崩断。这种故障只在模拟里做。
- 另外测两项：
  - 学校弹簧秤竖放和横放时的零点偏移：至少 3 把，每把至少 10 次
  - 至少 6 次"修正后复测"的预测验证（探索性）
- 只记录器材读数：不拍照，不记录任何人的信息。

## 6. 模型升级细节

- **改哪部分**：Qwen/Qwen3.5-4B 的语言部分。
  - bf16 LoRA，r=16，α=32，dropout 0.05。
  - 先确认 4B 的 index 文件（只有几 KB）里的模块名和 mlx-vlm 一一对应。对应的话，就覆盖语言部分所有线性层；不对应就只覆盖注意力层和 MLP，适配器约 42 MB。
  - 冻结视觉塔、词嵌入和 lm_head。用非思考格式，只对助手输出的 token 计算损失。
- **教给模型的技能**：
  - 输入：实验卡；候选原因（只给通俗的物理描述，不给特征标签）；1 到 8 行数据；特征面板；3 到 6 项追加测量组成的菜单。
  - 输出一个固定的 JSON：简短的证据和数据特征；每个原因预测的特征类型和概率；p(以上都不是)；最有信息量的下一次测量，以及排名前两位的原因各自对应的预期结果；z 结论；不超过 80 字的中文或英文解释。
  - 20% 的样本不给候选清单，要模型自己提出最多 6 个原因。
- **数据**：
  - 约 20,000 条提示，最终数量按实测吞吐量定。在服务器上由带随机种子的 labsim 代码生成，内容是 6 个课内实验加程序化任务族。
  - 标签全部来自引擎：后验概率（取整到 0.05）、EIG 最大的那项测量、每个原因的特征标签，以及模板化的双语解释（每个槽位有 3 种措辞）。
  - 原因的编号和顺序随机打乱，不同故障的大小先验相互重叠。
  - 没有人工标签、API 输出或学生数据。只上传代码。
- **训练**：
  - S1，引擎目标 SFT（主臂）：一次限时运行（不超过 2 小时或 2 个 epoch），只用一个预先指定的检查点。
  - 打乱标签对照：同样的提示、步数和种子，每个样本里的原因标签（包括"只有随机误差"）随机置换。
  - S3 GRPO（奖励函数相同，再加对 S1 的 KL 惩罚）：只有 S1 和对照都完成、GPU 空着时才跑，否则放进 Phase 2。文献预期 RL 比 SFT 迁移得更好，所以它排在 S2 前面。
  - S2 专家迭代：11 月不做，保留在计划里。
  - 上线规则：默认上线 S1；只有当 S3 相对 S1 提升的置信区间下界大于 0 时才换成 S3。E5 开始之前定死上线哪个模型。
- **服务器**（RTX 5090，32 GB）：
  - 环境：PyTorch CUDA ≥ 12.8（sm_120 需要）、transformers ≥ 5.2、flash-linear-attention、causal-conv1d。
  - 训练和推理分开使用 venv 或容器，用合并后的检查点交接。训练首选 Unsloth，不行依次退到 ms-swift、PEFT/TRL；推理用 vLLM，不行退到 HF 批量生成。
  - 11/6 只装环境，用 0.8B 跑 10 步冒烟测试（输出丢弃），记录快速路径有没有生效、每秒多少 token。
  - 租之前先确认服务器能连上 Hugging Face 或 ModelScope。
- **Mac 兜底训练**（只在服务器训练栈失败时用）：用 mlx-vlm 在 4-bit 底座上训练。它要预先登记为另一个更小的对比组，叫"S1-mac"，不冒充 S1，并且不和 27B 在同一晚跑。
- **为什么用 4B，不用 27B**：
  - 27B 做 bf16 LoRA 约需 56 GB 显存，超过显卡的 32 GB。
  - Unsloth 不建议对这一系列模型做 QLoRA。
  - 27B 单独加载就要占 24 GB 上限中的 18.5 到 23.5 GB，不能和 app 同时开。

  27B 的角色是"同一台 Mac 上的零样本大模型"，拿来和微调后的小专家比较。

## 9. 算力和内存

**Mac（24 GB 硬上限）**
- 产品模式：4B 服务 4.2 到 5.9 GB，Streamlit 0.3 到 0.5 GB，YOLO 0.6 到 1.0 GB，引擎不超过 0.3 GB，一个浏览器标签页 0.5 到 1.0 GB，合计约 5.9 到 8.7 GB。这是估计值，11/9 实测。
- 27B 基线之夜：
  - 先退出 Bionic 和 LM Studio，关掉 JIT 自动加载。端口 1234 上只要来一次误请求，就会再加载一份 16 到 20 GB 的模型。
  - 设 HF_HUB_OFFLINE=1，防止 mlx-vlm 再下载一份 16 GB。
  - 模型本身估计 18.5 到 23.5 GB，评测客户端另占不到 0.5 GB。
  - 同时不跑 Streamlit、YOLO、浏览器和 CPU 批任务。两个大模型永远不同时加载。
- CPU 任务（图谱、引擎验证、闭环、测试集生成）：最多 4 个进程，合计不到 2 GB，不和基线之夜重叠。27B 只在所有 CPU 任务都退出之后才启动。
- 磁盘：27B 16.08 GB、4B 3.06 GB、适配器不到 0.5 GB、环境和数据 2 到 3 GB，合计约 22 到 23 GB，剩余约 16 GB。11 月不在 Mac 上放 9B、bf16 底座或融合过的 27B。

**RTX 5090**（11/6 租到 11/10 左右，任务严格串行）
- 核心工作约 8 到 14 个 GPU 小时：
  - 训练池生成：10 到 20 分钟 CPU
  - 未微调模型评测：不到 1 小时
  - S1 训练：不超过 2 小时
  - 合并加评测：不到 1 小时
  - 打乱标签对照：1 到 2 小时，加评测
  - 消融和 3-shot：不到 1 小时
  - PhyX：不到 0.5 小时
  - S3 GRPO 另需 4 到 8 小时，只在 GPU 空闲时跑
- 显存：4B bf16 LoRA 约 10 GB（Unsloth 给的数据，序列长度在第一次运行时核实）；vLLM 服务合并后的 4B 约 20 到 22 GB；GRPO 16 到 28 GB。
- 传输：上行只有代码（KB 级）和冻结测试集（约 2 MB）；下行是适配器（约 42 到 65 MB）和 JSONL 结果（几十 MB）。

| 风险 | 应对 |
|---|---|
| 计划或签字晚于 11/7 | 11/5 之前所有工具做到一键可用；正式步骤顺延；先砍 P1 的内容，对照组绝不砍 |

## 16. 两个评测基准（物理 bench、识别 bench）

> 2026-11-05 新增。这一节是写给施工者（我、GPT）的工程规格，不是研究计划。目标怎么表述、margin 取多少、α 取多少、主指标选哪个，都由你在自己的研究计划里亲笔定，本节只留空位，不填数字。本节复用 §5.7、§7、§8 已经定义的冻结集和规则，**不新造样本量**；与实施计划冲突时，以实施计划为准。对照模型的调研原文在 `docs/isef/bench-comparators.md`。

### 16.1 为什么要两个 bench，各回答什么

| | 物理 bench | 识别 bench |
|---|---|---|
| 要回答的问题 | 微调后的 4B 在"找出力学数据背后的系统误差来源、选出下一次测量"上，和未微调 4B、27B、强 API 模型比起来怎么样？ | 微调后的 4B 看一张实验照片，能不能认出是哪个实验、有什么配置线索、有哪些器材，和其他视觉语言模型比起来怎么样？ |
| 对应产品功能 | §5.2、§5.3、§5.8（诊断、EIG、解释） | §5.12（开放集识别） |
| 对应实验 | E2、E4（以及 K1、K3） | E7 |
| 11 月 | 做（第 1 层、第 2 层，见 §16.7） | 只做一个小的描述性检查；正式 bench 放到 Phase 2 |

两个 bench 的共同点：**先冻结，再比较**。冻结之前，任何模型（包括你的微调模型）都不能碰 bench。

### 16.2 共同规则（两个 bench 都适用）

**冻结与隔离**
- bench 由 `lab_detective/eval/freeze` 生成清单（样本编号、所属 split、实验、随机种子、哈希），整体算 SHA-256，哈希和日期由你写进研究计划和实验记录本。启动器发现计划里没有这个哈希，就拒绝运行（§5.7）。
- 数据分四块：训练池、验证集（只用于早停和选检查点，§7 的 300 例）、dev 集（只用于调提示词和解码设置）、bench。验证集不够用时另划 dev 集，仍然在 bench 冻结之前。bench 与训练池、dev 集用不同的随机种子，并跑 K2 泄漏检查。
- **提示词、解码设置、被比较的检查点**（S1，或达到上线条件的 S3，见 §6）都在 bench 冻结之前、用验证集或 dev 集定死。3-shot 的示例只能取自训练池。
- 冻结之后，bench 里不改一条样本、一个标签、一个评分脚本。发现 bench 本身有错误时，不在原地修：作废、写一条 Project Addendum，另起一个新版本，所有 arm 重跑，旧结果保留在日志里。

**配对对照子集**
- API 每个模型不超过 600 例，27B 一晚只能跑 500 到 600 例（§7）。所以要在 bench 里固定种子、按实验和原因分层抽出一个"对照子集"，**和 bench 一起哈希**。所有 arm 都在这个子集上做配对比较，包括你的微调 4B。
- 本地 arm（S1、打乱标签对照、未微调 4B）另外在全量 bench 上报告。

**统一契约**（"同一提示、同一 schema、同一预算"的具体含义）
- 同一份提示契约和 JSON schema（§5.7），同一个解析器，贪心解码，`max_new_tokens` 不少于 1,024。非法输出和截断一律算错，逐 arm 报告非法率和截断率。
- 约束解码的强度本来不一样：本地 mlx_vlm 能按 schema 约束解码，API 只有 `json_object` 模式。冻结前二选一并写死：①所有 arm 都不用约束解码（本地也关掉），非法输出照算错；②保留约束，但在报告里把这一差异单列。开发侧建议①，因为它让各 arm 的条件最接近。
- DeepSeek 的 JSON 模式要求提示里出现 "json" 这个词并给出格式示例（见 `bench-comparators.md`）。这句话写进共享的提示契约，所有 arm 都带上，保证各 arm 看到的提示一字不差。
- **主表只用非思考档。** 思考档（high 强度）只当天花板参考，因为输出预算不同，不进入下面 §16.6 的非劣效判定。
- **K1 每个 arm 都要先跑**（包括每个 API arm）：把正确答案直接放进提示，准确率应接近满分，否则解析器或评分链路出错会被误读成"模型弱"。K3 换表对照同理（§4）。

**记录**
- 每次调用记录：日期、返回里的 `model` 字段、完整参数（思考开关、强度、temperature、`max_tokens`）、完整提示和回复，存成 JSONL（§5.7、§8 D7）。
- 每个 API arm 在一个很短的时间窗内跑完（建议同一天）。窗口内厂商更新了模型，这个 arm 作废重跑。
- 别名会漂移：`deepseek-v4-flash` 现在实际指向 V4.1-Flash-1017，以后可能再变。结果表里写"在某日期、返回的 `model` 字段为某某"，不写别名。
- 正式运行只有你能启动（§5.7）。API 输出只作评测基线，**绝不进入产品，也不进入训练数据**（§8）。

- 它太大，**不能在本机运行**（本机有 24 GB 上限），只能走 API。

- 思考默认开启，必须显式关闭才是"非思考档"。V4-Flash 的非思考与 Max 模式在 GPQA Diamond 上差 17 分（厂商自报），说明关掉思考后它明显变弱，所以两档要分开报，不要混在一起。
- **没有找到任何 DeepSeek V4 系列在 PhyX、PhysBench、OlympiadBench 上的公开数字**。所以你自建的物理 bench 就是这个对比的唯一依据；GPQA、HLE 这类科学推理基准只能当 sanity check，和"校园力学实验的系统误差归因"差距很大。
- 已排除：GLM-5V-Turbo（不是开放权重，不适合当开放权重对照）；InternVL 2026 年的新版本没查到（未核实）。

### 16.4 物理 bench

**目的**：在你自建、冻结的力学数据集上，对比各 arm 的原因识别和下一次测量建议。它是主线 C 的执行载体（§4），再加上"和强模型比"的外部参照，**不是一个新的主假设**。

**测试集构成**（全部复用 §7 的冻结集，不新造样本量；由 `labsim` 生成，Mac 上生成一次，由你启动）

| 子集 | 来源 | 回答什么 |
|---|---|---|
| 留出实验 | E4：6 个留出实验（斜面摩擦、阿特伍德机、自由落体、单摆、平抛、杠杆）每个 120 例，含"提出原因"任务（§6 里不给候选清单的那 20%） | 迁移到训练中没出现过的实验 |
| 同分布 | E2：同分布 600 例 | 基本能力 |
| 噪声偏移、留出原因 | E2：各 300 例 | 迁移阶梯 |
| 高保真错配世界 | §5.6 的 300 例鲁棒性集 | 引擎从不建模的效应下是否还稳 |
| 对照类样本 | E2：干净 150（误报率）、未建模 150（可检测与退化两类，考"不在清单"的诚实度）；K1（答案进提示）、K3（换表） | 评测链路和 arm 本身没有作弊或偷懒 |
| 配对对照子集 | §16.2：从上面各块分层抽出，和 bench 一起哈希 | 所有 arm 的配对比较 |

真实实验 E5 的 24 次**不属于**这个冻结 bench：它们是在实验做完、数据冻结之后，作为单独的一行报告（§4 主线 B 的真实检验）。

**指标**（主指标只能选一个，写进计划；其余都是描述性的）
- 等价类上的 top-1 准确率（§4 主线 C）；也可只在可辨识子集上算。
- 全部样本的 log score、Brier 分数；校准用 ECE。
- 干净数据上的误报率；未建模集上"不在我的清单里"的诚实度。
- 下一次测量：选中的测量与引擎 EIG 最优的一致率，以及 EIG 遗憾值。
- z 结论的正确率。
- JSON 合法率、截断率、输出 token 数。
- 归一化：(acc − chance) / (Bayes − chance)（§5.7）。
- 统计：精确 McNemar（配对）、Wilson 和 Clopper-Pearson 区间、配对 bootstrap、Holm 校正；跨实验用精确符号检验，并写明 n = 6 时它的局限（§4）。

**arm**（各方用同一提示、同一 schema、同一预算，见 §16.2）

| arm | 运行位置 | 在哪一档 |
|---|---|---|
| S1（你的微调 4B） | 服务器训练，合并后评测 | 第 1 层 |
| 打乱标签对照 | 服务器 | 第 1 层 |
| 未微调 4B：零样本、3-shot | 服务器 | 第 1 层 |
| 开启思考的 4B、去掉特征面板的消融 | 服务器 | 第 2 层 |
| 梯度提升树、规则匹配器 | Mac CPU | 第 1 层 |
| Qwen3.8-27B 非思考（思考档可选） | Mac，夜里单独跑，对照子集 | 第 2 层 |
| DeepSeek-V4.1-Flash 非思考（主）、high 思考（天花板） | 官方 API，对照子集 | 第 2 层 |
| 其他 API 对照（Gemma 4 31B 等） | 可选 | §7 规定 API 模型 1 到 2 个，预算冲突时以此为准 |

**解释结果的口径**：只能说"在你自建的这个物理 bench 上，微调的 4B 相当于或接近某某基线"，不能外推成通用物理能力。通用物理能力是否退化，由 PhyX 的等价检验单独回答（§4），不属于这个 bench。

### 16.5 识别 bench

**目的**：评估 §5.12 的开放集识别：看一张实验照片，给出单字母代码（A 到 F 是六个课内实验，G 是其他）、开放的实验名称、配置线索、器材清单。Phase 2 的视觉侧 LoRA（§5.13）如果做出来，作为另一个 arm 另行登记。

> 2026-11-05 更新：本节和下面规则里的"A 到 F / G 是其他 / A 到 G 的标签表"以 `vision/letters.py` 为准：A–F 课内、G–L 留出、**Z = 其他**。开发侧已实现切分、生成、打分和审核图册，接口与诚实度约定写在 `docs/ARCHITECTURE.md` §2.6（工程规格，不含 margin、Δ、α、主指标——那些仍由学生亲笔定）。

**测试集构成与来源规则**（沿用 §8 的 D4、D5）

| 来源 | 说明 |
|---|---|
| 你本人拍的照片 | 你已确认 self_captured 里的照片是你本人拍的、没有人像；来自 GitHub 上的 `data/dataset.zip`（§3 写的是 809 张标注图：241 张照片加 3 个视频的 568 帧） |
| 来源已确认的数据集照片 | 授权清楚、图中只有器材；授权不清的视频帧一律排除，也永远不展示 |
| 外部 CC 图片 | Wikimedia Commons，以及 Getaclass（CC BY 3.0）、Wikiexperiments（CC BY-SA 4.0）视频的关键帧；清单里每张记标题、作者、URL、许可、sha1；遵守 API 速率限制；目标 150 到 300 张，数量不保证 |
| 最小对照图片对 | 两张图只在一个关键配置线索上不同（比如滑轮下挂不挂重物、两车相对还是同向、轨道倾斜与否、测力计水平还是竖直）。改过的图片是否仍被原授权覆盖，要由你核对（§8 D4）；能用你自己拍的就优先 |

规则：
- **来源登记**：每张图记录来源、作者、URL、许可、sha1、是否你本人拍摄、是否进过 YOLO 训练集、人像检查结果。
- **人像**：用项目里已有的 COCO `yolov8n.pt` 筛出含人像的图片，模糊、裁掉或排除；**发给任何 API 之前再检查一次**，不能含人脸或个人信息。
- **标签由你亲自定并核实**。AI 收集到的只是候选素材，不给图片贴标签。
- **bench 用的照片要在开发使用之前就划出来**：E8 的断网测试和产品调试会用到你拍的照片，bench 用的那批不能进入 E8 调试、提示词调整或 YOLO 重训。
- **未核实**：§3 说 dataset.zip 的 809 张标注图在 GitHub 仓库里，它们很可能就是现有 YOLO 的训练或验证数据，但我没有核对。如果是，"规则优先"的流水线在这些图上的成绩会偏高：要么按"是否进过 YOLO 训练集"分层报告，要么只报 VLM-only 的结果。核实之前，两种口径都按上面的字段留位置。（2026-11-05 更新：已核对 `results/recognition/manifest.jsonl`——200 张本人照片都带 `yolo_split`，其中 167 张在 YOLO 训练集、23 张在验证集、10 张在 YOLO 测试集，所以"规则 + YOLO 检测框"必须按 `yolo_split` 分层报告；YOLO 当年按帧随机划分，连拍的相邻帧也在它的训练集里。）
- **视觉语言模型 arm 与规则流水线分开报**：规则流水线（YOLO 加规则）作为参考组单列，不和 VLM 混成一个数。
- 所有 arm 共用同一份 A 到 G 的标签表（现为 A–L + Z，见上面的更新说明），提示词允许输出"未知/不在列表内"；"未知"和 Z 怎么计分，由你在冻结前定死（评分脚本有 `invalid_as` 开关，默认非法输出算错）。bench 里要包含不属于六个课内实验的图，才能测开放集。
- 图片不超过 1024 px，带编号框（Set-of-Mark，§5.12），对所有 arm 一致。

**指标**
- 单字母 top-1 准确率，每类召回和混淆矩阵。
- 开放实验名称的命中率：评分用一张你冻结的同义词表，或者由你亲自评，不用另一个 LLM 当评委。
- 配置线索和器材清单的 F1（对照你写的参考答案）。
- 最小对照图片对：成对一致率（两张都对才算对）。
- 开放集拒答：AUROC。保形预测的候选集覆盖率和集合大小放到 Phase 2。
- JSON 合法率、延迟，以及按来源分层的结果。
- 统计：Wilson 区间、精确 McNemar（配对）、按来源分层、Holm 校正。

**arm**：S1；未微调 4B；Gemma 4 31B-it 和 Qwen3.8-27B（同属开放权重的稠密模型，量级与学生模型最接近）；DeepSeek-V4.1-Flash（用户点名对标的强基线，必须写成 V4.1-Flash）；Kimi K3 可选，只作上限参考；YOLO 加规则流水线作参考组。27B 在 Mac 上加载时图片加模型会贴着 24 GB 上限，只能夜里单独跑（§9）。

**11 月只做小的描述性检查**：用你本人拍的少量照片（数量由你定），比较 S1 和未微调 4B（可选再加一个 API 模型），只报告数字和 Wilson 区间，**不做非劣效或优效声明**。正式 bench 和 §16.6 的目标放到 Phase 2，使用来源已确认的照片和 CC 图片。

### 16.6 预先登记的目标，以及完整性规则

**你的目标**（你的原话）：微调模型基本持平或超过 DeepSeek-V4-Flash 这类强开源模型。

下面把它写成一个**预先登记的非劣效、再优效**目标。表述的结构由开发侧给出，所有数值由你定：

| 要登记的项 | 内容 |
|---|---|
| 对比双方 | 你的微调模型（S1，或达到上线条件的 S3）对 DeepSeek-V4.1-Flash 非思考档；在配对对照子集上 |
| 主指标 | 〔你定〕，只选一个（例如物理 bench 的等价类 top-1） |
| 目标适用的子集 | 〔你定〕，建议只选一个（例如 6 个留出实验合并的对照子集） |
| 非劣效 margin Δ | 〔你定〕 |
| 显著性水平 α、单侧还是双侧 | 〔你定〕 |
| 检验方法 | 〔你定〕；结构：配对差值的置信区间下界与 −Δ 比较（配对 bootstrap，或基于精确 McNemar 的区间） |
| 判定顺序 | 固定：先检验非劣效；非劣效成立之后，再检验优效（差值的下界是否大于 0）；顺序不能事后换 |
| 样本量与功效 | 〔你定〕；n 只有几百时，Δ 取得太小会功效不足，Δ 和 n 互相制约，功效计算由你自己做 |
| 登记位置 | 你亲笔写的研究计划；日期和 bench 哈希写进实验记录本 |

开发侧不提供任何数值，也不预设"达到才算成功"。

**这个目标在整套检验里的位置**：
- §4 把"和 API 模型的比较"放在 Holm 校正的次要分析里，把"和 27B 的比较"限定为只给估计值和置信区间、不做非劣效声明。本节保持这两条不变：**非劣效目标只针对 V4.1-Flash 的非思考档**；27B 仍然是描述性比较。
- 这个目标不能变成和主线 C 竞争的新主假设。它在检验层级的哪一层、要不要纳入 Holm 校正，由你在计划里定。
- 思考档（high）不进入这个判定，只当天花板参考。
- 它属于第 2 层（需要 API key 和预算）。时间紧需要砍的时候，按实施计划的顺序砍（27B、API、PhyX、开启思考的参考组），被砍的目标标"未执行"，不能悄悄从报告里删掉。

**完整性规则**（这是整个 bench 的底线）
1. **先冻结，后比较。** bench 在任何模型被比较之前冻结并哈希；冻结后不改样本、标签、评分脚本、子集、指标和 Δ。看到结果之后发现 bench 有错，走 §16.2 的"作废、Addendum、新版本、全部 arm 重跑"流程，不原地修。
2. **结果照实报告。** 目标没达到，就写没达到；报告里列出 §16.3 的所有 arm，不能因为某个 arm 难看就拿掉。某个 arm 没跑成（比如 API 不可用），写"缺失"和原因。
3. **达标靠训练，不靠调 bench。** 我们追这个目标的办法是：引擎标注的数据、程序化任务族、打乱标签对照这样的严格对照。不允许的做法：把 bench 的样本或变体放进训练；用 bench 选提示词、检查点或超参；把 API 或其他对比模型的输出当训练数据或蒸馏对象。
4. **口径谨慎。** 结论只能写成"在你自建的这个 bench 上，微调的 4B 相当于或接近某某基线"，不外推成通用能力。bench 与训练数据严格隔离（K2 泄漏检查加不同随机种子）。
5. **每个 API 基线都是一次快照。** 它在某个日期、某个返回的 `model` 字段下的结果，不代表别名将来指向的模型。
6. **Rule 8。** 本节和 `bench-comparators.md` 里的网址只是评测方案和工程文档的参考。若将来要写进论文或海报的参考文献，请你自己核对原始页面、自己整理引用，不要照搬 AI 给出的列表。目标的表述、Δ、α、结论都由你亲笔写。
