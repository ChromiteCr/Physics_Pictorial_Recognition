## 1. 一句话，和为什么选它

**一句话**：一个完全离线的中学力学实验 AI 伙伴。拍一张装置的照片，它认出实验，把装置变成可计算的**物理孪生**；
带学生先预测、再测量、边测边对照；数据偏离理论时，用贝叶斯推断找出最能解释数据的系统误差来源（比如摩擦没平衡、弹簧秤竖着调零却横着用），
数据分不清时直说分不清，并指出能把这些原因分开的那一次测量；最后依据物理事实单讲解，并关联到知识点。
物理引擎同时充当"老师"：不用人工标注，就能训练一个 4B 的视觉语言模型。项目要测的是：这种能力能迁移到多少训练中没见过的实验上。

**为什么选它**
- 老师要求"在大模型上动刀"。这里模型权重确实会改变（LoRA 微调），并且有对照实验证明改变来自物理引擎的标注，不是模型学会了输出格式。
- 科学问题直接长在教学系统里：课程标准要求"分析误差来源，提出减小误差的方法"，旧系统只会说"相对误差 < 15% 就算验证成功"。
- 物理含量高：误差物理孪生、物理组件层、可辨识性图谱、不确定度预算、信息增益，这些是物理加测量学的内容，不是调用别人的模型。
- "实践"和"闭环"由学生本人在真实器材上故意注入故障来完成。这条路只有学生本人操作，不涉及其他人类参与者。
- 与已有工作的区别（尤其是格物论文，见 `innovation-and-boundaries.md`）：没有代码沙箱、没有工具调用循环、没有投票、不做文本题辅导；模型从不自己算物理。

## 2. 目标、非目标、反目标

**目标**
1. **通用的力学实验伙伴**：能识别开放集的力学装置；已精修的课内与留出实验只是起点，其余装置由物理组件层组合，组件也拼不出的装置走"其他实验"通道。**不声称任何固定的支持实验总数。**
2. **探究式教学**：实验前预测、实验中实时一致性检查、先让学生自己猜嫌疑人再揭示引擎排名、按信息增益推荐下一次测量、误差与知识点关联、修正后复测。
3. **技术升级落在模型上**：用引擎标注的数据（加不超过 5,248 条经引擎一致性过滤的蒸馏样本）对 Qwen3.5-4B 做 LoRA 微调，再和未微调的 4B、Qwen3.8-27B、DeepSeek V4.1 Flash 等比较；各方用同一份提示、同一种输出格式。
4. **科学问题可证伪**：有预先登记的目标、对照组和统计检验；零结果和负结果同样如实报告。
5. **产品完全离线**：不调用任何外部模型或 API；API 模型只在评测里当对照组、在离线构建数据时当蒸馏教师。
6. **模型从不算物理**：数字全部来自确定性代码（事实单 FactSheet），讲解过声明校验器，过不了换模板；有脚本化兜底。
7. 11/15 交带结果的完整项目（学生 2026-11-05 已确认），所以 11/14 前必须有结果。

**非目标**（11 月不做，写进计划的后续阶段）
- 让模型读仪表示数（MeasureBench 上最好的模型在真实图片上只有 30.3%，读数继续手填）。
- 视觉侧微调、9B、27B 微调、视频输入。
- 识别准确率的正式声明（照片来源与数量见 §9；11 月只做描述性比较）。
- 展位"评委挑战"游戏和教师端协议视图。

**反目标**（功能就算跑通，出现这些也算失败）
- 研究计划或摘要被认定为 AI 撰写，或者引用了 AI 提供、学生自己没读过的文献。
- 没有 IRB 批准，就有学生以外的人使用或测试 app，并且算进了项目。
- 展示编造的"过去结果"，或描述学生并没有的器材（例如钢球实验）。
- 本机同时运行的进程合计超过 24 GB 内存。
- 声称"8 GB 的学校电脑能跑"，却从没在那种机器上测过。
- 把 bench 的样本或变体放进训练，或用 bench 选提示词、检查点、超参。

## 3. 约束（已核实）

**时间**
- 2026-11-05 学生批准开工，代码在 `p2-lab-detective` 分支。2026-11-06 起租用 RTX 5090（有 SSH；平台、计费、能否连 Hugging Face 以当天确认为准）。
- 11/15 交带结果的完整项目；11/14 前必须有结果。正式运行最早在研究计划写完、表格签好、物理卡审核完之后开始（见 §12）。

**硬件**
- Mac M4 Pro 48 GB。硬上限：我们启动的所有进程合计不超过 24 GB，超了先停最简单的任务。磁盘紧张。
- RTX 5090（32 GB）。上传只有约 100 KB/s，所以只传代码、小文件和训练包（打包脚本会报告预计上传时间）。

**模型**
- Qwen3.5-4B：Apache-2.0，原生支持图像，是产品的底座；MLX 4-bit 约 3 GB。
- Qwen3.8-27B：本地 MLX 4-bit 约 16 GB，单独加载时已贴着 24 GB 上限，只能夜里单独跑，只当对照组。
- 微调后的适配器用 `mlx_vlm.server` 提供服务（它支持适配器、JSON schema、logprobs，并且可显式关闭思考）。LM Studio 不能加载 LoRA 适配器，**只作为下载底座的来源或对照组的本地运行器，不是产品的服务器**。

**数据**
- 没有任何公开的"学生原始测量数据"数据集。主数据是模拟器生成的合成数据，再加上学生本人在真实器材上的测量。
- 学生本人拍摄的照片（无人像）在本机 `datasets/`，其中进入识别流水线的 200 张照片的标签仍待学生审核；其余来源（网图、视频帧）授权不清的一律不展示、不用作评测。

**ISEF 规则（2026 到 27 年度，已核实）**
- 除学生本人以外，任何人使用或测试 app，或者做问卷、请老师打分、分析同学的数据，都算人类参与者研究：先由学校 3 人 IRB 签 Form 4，再取得未成年人的书面同意和家长许可。只有学生自己测试时才豁免。
- 研究计划由学生本人写，并在开始实验前签好 Form 1、1A、1B（需要时还有 Form 3）。新的 Form 2A 要求披露 AI 使用，并附提示记录。
- 生成式 AI 不能写研究计划、摘要、海报、论文初稿、结论和未来工作，也不能提供引用或"起步参考文献"。AI 写的代码必须标明。
- 延续项目要填 Form 7，展板和摘要只展示新工作。之前五次课堂使用的结果不能当作 ISEF 结果。
- 最合适的类别是 ROBO（Machine Learning）；若想让图谱当头条，可改为 PHYS（Mechanics），内容不变。展位必须在离线状态下可用。

## 4. 产品设计

### 4.1 流程（五步界面，`app.py` + `ui/`）

| 步骤 | 内容 |
|---|---|
| ① 拍照识别 | YOLO 器材框 + 画布修正；规则优先，本地视觉语言模型兜底，仍分不开则问一个澄清问题；**手动选择永远可用且不被覆盖**；不在表里的装置走"其他实验" |
| ② 实验设计 | 学生先写下自己的预测（或明确跳过），之后才显示孪生的预期；不确定度预算；本方案分不开哪些原因；建议的测量范围 |
| ③ 测量 | 多行数据表（按方案和仪器配置预填控制量），填完一行就与孪生实时对照（z 值和提示） |
| ④ 诊断 | 一致性 → 先猜原因 → 嫌疑人看板（概率条 + 证据）→ 幽灵曲线 → "下一次测量"卡（各嫌疑人的预测值）→ 修正后复测验证 |
| ⑤ 讲解 | 依据事实单讲解（脚本模式用模板；模型模式由本地模型写、校验器把关）；知识点与前置知识学习路径；学生自己写结论 |

产品默认**脚本模式**（模板，不需要任何模型）。侧栏的"模型模式"只连学生填写的本机地址。

### 4.2 物理层（本项目的主体）

- **精选实验孪生**（`labsim/experiments/`）：numpy 前向模型，模拟测量过程和仪器噪声，带系统误差物理和故障库（每个实验若干原因，其中一定有"只有随机误差"；每个原因带通俗描述、机制标签、修正方法、来源标签"文献"或"假设"）。
  当前的起点集合：训练侧为摩擦力、平均速度、胡克定律、牛顿第二定律（悬挂重物）、动量守恒、机械能守恒；留出侧为斜面摩擦、阿特伍德机、自由落体、单摆、平抛、杠杆。每个都经过独立的物理复核。它们是起点，不是固定集合。
- **物理组件层**（`physics/`，接口见 ARCHITECTURE §2.8）：物体、连接件、表面、仪器 + 规律模板，`Setup` 组合成与精选实验同接口的孪生，引擎等下游模块不用改。镜像精选实验时，每个原因、每种观测的读数均值和标准差逐项一致；另有新组合（斜面牛二、系统机械能、弹簧振子、光电门自由落体、斜面下滑）默认留出，做迁移测试。
  `from_photo.py` 把识别出的器材和线索变成候选装置和"还要学生补的已知量"（质量、倾角、遮光片宽度……）。
- **通用关系族与故障算子**（`labsim/generic.py`）：组件也拼不出时的退路，也是训练里的"程序化任务族"（随机线性化定律、随机命名变量、偏移/比例/弯曲/散布/漂移等通用故障，多样的物理语言描述），让模型从大量"描述 → 特征"映射里学，而不是死记几十条。
- **贝叶斯诊断引擎**（`engine.py`）：计算 {只有随机误差、原因 1…K、以上都不是} 的后验。非线性参数（干扰量、故障幅度）放网格，线性参数解析积分（解析积分已与暴力积分对照验证）；失配统计量按模拟校准到固定误报率，超过即提示"原因不在我的清单里"。
  一致性用 z = (测量值 − 预测值) / 合成标准不确定度；取代旧的"相对误差 < 15%"规则。
- **特征面板**（`panel.py`）：数据特征只用可观测量——截距、斜率比、曲率、散布偏大/偏小、漂移。所有对比组拿到完全相同的面板，所以提升不可能来自"模型学会了算术"。
- **EIG 与闭环**（`eig.py`）：对每项追加测量蒙特卡洛估计期望信息增益，推荐最好的一项并在动手前给出每个嫌疑人的预测读数；菜单里没有任何测量能分开剩余嫌疑人时直说。
- **可辨识性图谱**（`atlas.py`）：对每个方案（单次、标准、标准 + 追加测量、标准 + EIG/随机）算贝叶斯最优两两判别的正确率区间，回答"课本标准方案分不开哪些原因、哪一次测量能分开"。
  例（可在白板上推）：胡克定律里漏算挂钩质量、刻度尺零点偏移、记录弹簧总长而不是伸长量，在斜率自由时都表现为 F–x 直线有截距，称一下挂钩、读一下空载长度即可分开。
- **不确定度预算**（`uncertainty.py`）与**孪生/幽灵曲线**（`twin.py`）：实验前的预期读数及其来源份额；幽灵曲线显示"若是原因 X，曲线应当长这样"。
- **事实单**（`facts.py`）：引擎输出的唯一出口（数字、单位、方向、嫌疑人排名与证据、下一次测量、修正与复测预测、相关知识点）；讲解与校验器共用。

### 4.3 教学与语言层

- **知识点图谱与实验卡**（`knowledge/`）：知识点、前置关系、常见误解与症状，实验卡含目的、原理、变量、步骤、安全提示。
- **探究式导师**（`tutor/`）：会话状态机（识别 → 计划 → 预测 → 测量 → 检查 → 诊断 → 讲解 → 反思），按阶段只放必要信息的上下文组装（不放完整对话历史），脚本导师有 0 到 3 级提示阶梯。
- **声明校验器**（`tutor/verifier.py`）：抽出讲解里的数字、单位、方向词、原因名称、推荐测量，逐一与事实单核对，并要求覆盖"主要原因、一个数值证据、下一次测量"。模型可改写一次，仍不通过则换模板。宽严取舍：误杀正确讲解的代价大于放过可疑说法。
- **识别**（`vision/`）：规则读 YOLO 线索，模型兜底看一张带编号框（Set-of-Mark）的照片，按固定 JSON schema 输出字母代码、开放实验名、配置线索、器材清单。字母表见 `vision/letters.py`（课内与留出实验各一个大写字母，Z = 其他）。澄清问题从固定题库里按期望熵减最大选一题。
- **其他实验通道**：学生从菜单选变量和关系类型，代码算通用特征面板；模型给出的内容一律标"AI 估计，未经物理验证"。

### 4.4 真实器材闭环（`fieldkit/`，只由学生本人操作）

- 规模：约 3 个实验 × 4 种条件（干净 + 3 种故障）× 2 次重复。胡克；摩擦或牛二（看学校器材）；一个留出实验（如单摆，走"其他实验"通道，手机传感器计时避免反应时间）。
- 故障尽量由在场负责安全监督的成年人按密封卡设置（一眼看不出的故障：弹簧秤零点、贴错标签的钩码质量、遮光片宽度的录入）。成年人只做安全监督和设置，不记录关于这位成年人的任何数据，并在 Form 2A 里列出这项帮助。学生自己设置的故障标"未盲"，作为局限写明。
- 预先提交的随机表（种子 + SHA-256 承诺）、记录表冻结后才交给软件；分析由学生本人启动，软件只输出数字。
- 不在真实弹簧上做"超过弹性限度"的故障（会损坏弹簧）；这类故障只在模拟里做。只记录器材读数：不拍照，不记录任何人的信息。
- 每次实验把三种追加测量都做一遍：EIG 推荐的、最佳固定测量（与 EIG 不同时才做）、一次重复，顺序按预先提交的随机表。

## 5. 模型与训练

**总原则**：产品里只用自己的基础模型加自己训练的适配器和自己的物理代码。

- **底座与适配**：Qwen3.5-4B 的语言部分，bf16 LoRA，r = 16、α = 32、dropout 0.05；先用名称核对确认 PEFT 与 mlx-vlm 的模块名一一对应，再决定是否把线性注意力投影加进目标；冻结视觉塔、词嵌入和 lm_head；非思考格式，只对助手输出的 token 算损失。
- **训练数据（来源与配比）**
  1. **引擎标注的样本**（主体）：诊断（含 20% 不给候选清单、让模型自己提出原因的变体；约 8% 真实原因不在清单里）、实验前设计、事实单讲解（必须过校验器）、知识点问答。诊断里程序化任务族与训练实验各约一半；原因编号和顺序随机打乱，故障大小的先验相互重叠。标签全部来自确定性代码，没有人工标签、API 输出或学生数据。提示词的唯一来源是 `training/prompts.py`（训练、蒸馏、bench、推理共用，改提示必须升版本）。详见 ARCHITECTURE §2.7。
  2. **经引擎一致性过滤的蒸馏样本**（≤ 5,248 条）：教师盲做，只保留与物理引擎判定一致的输出，训练提示保留教师当时看到的指令（ARCHITECTURE §2.9）。**唯一借鉴格物的做法**。
  3. 引导 / 识别 / 实验卡样本：脚本导师轨迹、学生本人照片的识别样本（排除识别 bench 的测试侧）、实验卡问答——开发中，落地后补进 ARCHITECTURE。
- **扣下的原因**：每个训练实验扣下一个原因（`splits.WITHHELD_CAUSES`）不参与训练，构成"已知实验里的新原因"测试；扣下哪个由学生确认。
- **训练臂**：S1（引擎目标 SFT，主臂，一次限时运行，只用预先指定的检查点）；打乱标签对照（相同提示、步数、种子和批次，只把原因标签随机置换，排除"只是学会了 JSON 格式"）。S3（GRPO）只在 S1 与对照都完成且 GPU 空着时跑，否则放进 Phase 2；S2 专家迭代 11 月不做。上线规则在 E5 开始前定死（默认 S1）。
- **服务器**（RTX 5090，今日起租）：训练栈与推理栈分开（训练用 PEFT/TRL 风格的自带脚本，推理优先 vLLM、退到 HF 生成）；CUDA ≥ 12.8；步骤全在 `server/README.md`；先 0.8B 冒烟再 4B 吞吐探针，再由学生启动正式运行。
- **部署与一致性闸门**：PEFT → mlx-vlm 转换器（带测试）；`mlx_vlm.server --adapter-path`，每个请求显式关闭思考并检查回复无推理文本。闸门：K0 token 一致性、200 例一致性测试、适配器效应检查、Mac 与服务器准确率的等价检验。闸门不过的退路：8-bit、"反量化—相加—再量化"融合（绝不用会丢掉视觉塔的 `mlx_lm.fuse`）、v1 先用未微调 4B 加引擎。
- **为什么 4B 不是 27B**：27B 做 bf16 LoRA 约需 56 GB 显存，超出 32 GB；27B 单独加载就占满 24 GB 上限。27B 的角色是"同一台 Mac 上的零样本大模型"，拿来和微调后的小专家比较。

## 6. 科学问题和要检验的主张

（下面是想法层面的表述，计划里的版本要学生自己写。）

**研究问题（草案）**：学生的力学实验数据偏离理论时，一个完全离线的系统能在多大程度上找出背后的系统误差来源，并选出最能区分各候选原因的下一次测量？只用物理引擎标注的数据训练出来的小型视觉语言模型，能把这种能力迁移到训练中没出现过的实验上吗？

**主线 A：可辨识性图谱**（预先规定的定量成果，不当作假设检验）：对每个实验、每种测量方案，用模拟算贝叶斯最优两两判别的区间；只有置信区间上界低于学生定的阈值才判为"混淆"；故障大小先验和噪声各做 ×0.5、×2 的敏感性分析。实证检验改为"预测效度"：学生的真实测量里，标准方案下引擎在图谱预测会混淆的那对原因上的表现是否落在图谱区间内。

**主线 B：闭环里的下一次测量**（确认性）：按 EIG 自适应选下一次测量，是否比"最佳固定追加测量"（独立校准集上平均效果最好的那一项）更能提高真实原因的后验概率。模拟部分放在"高保真错配世界"（含引擎从不建模的效应：滑轮惯量、空气阻力、绳子质量、偏态计时噪声、偶发抄写错误），用配对 Wilcoxon；真实部分用故障注入实验。

**主线 C：模型升级和迁移**（确认性，主要的机器学习主张）：S1 在留出实验上识别原因的表现是否优于打乱标签对照（精确 McNemar）；S1 相对未微调 4B（3-shot）的提升作为总效应。双侧检验；已有工作预测 SFT 的迁移可能失败（见 §15 线索），所以零结果或负结果同样有意义。指标是"等价类"上的 top-1（图谱判为完全混淆的原因合并成一类），同时报告 log score 和 Brier。结论只说"在这 N 个留出实验上"，逐个实验报告并做跨实验精确符号检验；留出实验少时该检验功效很低（需全部提升才可能 p < 0.05），Phase 2 再增加留出实验。

**次要分析**（Holm 校正）：迁移阶梯（同分布 → 噪声偏移 → 留出原因 → 高保真世界 → 近/远迁移实验）、EIG 遗憾值、校准（Brier、ECE）、干净数据误报率、解释忠实度、与 27B（只给估计与区间，不做非劣效声明）和 API 模型的比较、去掉特征面板的消融、开启思考的未微调 4B。

**解读任何结果之前必须先通过的对照**
- K0：训练格式与 Mac 服务路径对 20 个提示生成的 token ID 完全一致。 K1：把正确答案放进提示，准确率应接近满分（证明评测链路没坏），每个 arm 包括每个 API arm 都先跑。 K2：泄漏检查器能抓到故意放进去的重复样本。 K3：换表对照（保留原标签但数据表换成同实验另一个样本的）应降到机会水平，用等价区间判断。 K4：转换到 Mac 上的适配器确实改变了模型输出。 K5：去掉特征面板的消融。 K6：模型内数据上引擎校准良好（顺带检查网格积分）。

**升级不该改变的东西**：通用物理题（PhyX，至少 1,500 题，服务器上做等价检验 TOST）；照片识别 11 月只做描述性比较。

**工程指标**（通过/不通过，阈值由学生按实测值定）：EC1 断网可用、产品不调用外部 API；EC2 峰值内存，合计不超过 24 GB；EC3 延迟（引擎诊断在 1 秒内）；EC4 JSON 合法率；EC5 任何页面手动选择实验最多点 2 次且不被系统覆盖；EC6 Mac 与服务器一致性（参照未微调模型自身 bf16 版与 4-bit 版的一致率）；EC7 旧"相对误差 < 15%"规则全部删除，改按不确定度归一化的 z 一致性。

## 7. 评测基准（物理 bench、识别 bench）

> 这一节是写给施工者的工程规格，不是研究计划。目标怎么表述、margin 取多少、α 取多少、主指标选哪个，都由学生在自己的研究计划里亲笔定，本节只留空位，不填数字。

### 7.1 为什么要两个 bench

| | 物理 bench | 识别 bench |
|---|---|---|
| 要回答的问题 | 微调 4B 在"找出系统误差来源、选下一次测量"上，和未微调 4B、27B、强 API 模型比怎么样 | 微调 4B 看一张实验照片，能不能认出实验、配置线索和器材，和其他视觉语言模型比怎么样 |
| 对应功能 | 诊断、EIG、解释 | 开放集识别 |
| 对应实验 | E2、E4（以及 K1、K3） | E7 |
| 11 月 | 做第 1 层和第 2 层 | 只做小的描述性检查；正式 bench 放到 Phase 2 |

两个 bench 的共同点：**先冻结，再比较**。冻结之前，任何模型（包括微调模型）都不能碰 bench。

### 7.2 共同规则

- **冻结与隔离**：`bench/freeze.py` 为清单里每个文件算 SHA-256；哈希和日期由学生写进研究计划和实验记录本。**冻结命令只能由学生本人运行，开发侧从不调用。** 数据分四块：训练池、验证集（只用于早停和选检查点）、dev 集（只用于调提示词和解码设置）、bench；bench 与训练池、dev 集用不同随机种子并跑泄漏检查（K2）。提示词、解码设置、被比较的检查点都在冻结前定死；3-shot 示例只取自训练池。冻结后不改一条样本、标签或评分脚本；发现 bench 有错时作废、写 Project Addendum、另起新版本、所有 arm 重跑。
- **配对对照子集**：API 每个模型有数量上限，27B 一晚只能跑几百例，所以按实验和原因分层固定抽一个子集，**和 bench 一起哈希**，所有 arm 在这个子集上做配对比较；本地 arm 另在全量上报告。
- **统一契约**：同一份提示契约和 JSON schema、同一个解析器、贪心解码、`max_new_tokens` 不少于 1,024；非法输出和截断一律算错，逐 arm 报告非法率和截断率。约束解码的强度本来不同（本地能按 schema 约束，API 只有 `json_object`），冻结前二选一写死，开发侧建议所有 arm 都不用约束解码。DeepSeek 的 JSON 模式要求提示里出现 "json" 并给格式示例，这句话写进共享提示契约。**主表只用非思考档**；思考档只当天花板参考，不进入非劣效判定。
- **记录**：每次调用记日期、返回的 `model` 字段、完整参数、完整提示和回复（JSONL）；每个 API arm 在很短的时间窗内跑完；别名会漂移，结果表写"某日期、返回的 model 字段为某某"。正式运行只有学生能启动。API 输出只作评测基线，**绝不进入产品，也不进入训练数据**。

### 7.3 对比对象（调研摘要，调查日期 2026-11-05；全文与来源见 `bench-comparators.md`，厂商自报数字未经独立复现）

| 未微调 4B | Qwen3.5-4B | 两个都能 | 零样本、3-shot；物理 bench 另有开启思考版 |
| Qwen3.8-27B | `Qwen/Qwen3.8-27B` | 两个都能 | Apache 2.0；本地 MLX 4-bit 夜里单独跑；`enable_thinking:false` 关闭思考 |

### 7.4 物理 bench

**目的**：在自建、冻结的力学数据集上，对比各 arm 的原因识别和下一次测量建议。它是主线 C 的执行载体，再加上"和强模型比"的外部参照，**不是新的主假设**。

**构成**（由 `labsim` 生成，Mac 上生成一次，由学生启动；种子使用 bench 专用命名空间，训练与验证生成器从不使用）

| 子集 | 回答什么 |
|---|---|
| 留出实验（含"提出原因"任务） | 迁移到训练中没出现过的实验 |
| 同分布 | 基本能力 |
| 噪声偏移、留出原因 | 迁移阶梯 |
| 高保真错配世界 | 引擎从不建模的效应下是否还稳 |
| 对照类：干净数据（误报率）、未建模原因（"不在清单"的诚实度）、K1、K3 | 评测链路和 arm 本身没有作弊或偷懒 |
| 配对对照子集 | 所有 arm 的配对比较 |

各子集的样本量由学生冻结前定（见 §14）。真实实验的数据**不属于**这个冻结 bench，实验做完、数据冻结之后作为单独一行报告。

**指标**（主指标只选一个，写进计划；其余描述性）：等价类上的 top-1；log score、Brier、ECE；干净数据误报率；"不在清单"诚实度；下一次测量与引擎 EIG 最优的一致率及 EIG 遗憾值；z 结论正确率；JSON 合法率、截断率、输出 token 数；归一化 (acc − chance) / (Bayes − chance)。统计：精确 McNemar、Wilson 和 Clopper-Pearson 区间、配对 bootstrap、Holm、跨实验精确符号检验（`bench/stats.py`）。

**口径**：只能说"在自建的这个物理 bench 上，微调的 4B 相当于或接近某某基线"，不能外推成通用物理能力。

### 7.5 识别 bench

**目的**：评估开放集识别——单字母代码、开放实验名、配置线索、器材清单。接口与诚实度约定见 ARCHITECTURE §2.6（工程规格，不含 margin、Δ、α、主指标）。

- **来源规则**：学生本人拍摄的照片（标签由学生在审核图册里逐张确认；图册没有预选）；来源已确认的数据集照片；外部 CC 图片（Phase 2，逐张登记标题、作者、URL、许可、sha1）；最小对照图片对（Phase 2，改过的图片是否仍被原授权覆盖要核对）。
- **人像**：发给任何 API 之前必须再检查一次，不能含人脸或个人信息。授权不清的视频帧一律排除，也永远不展示。
- **按拍摄时段切分**：相邻照片间隔不超过 `gap_s` 算同一时段，整段进测试集；开发时看过的照片所在时段固定划进训练侧。训练样本生成必须排除测试侧并用 `check_no_overlap` 自查。当前 200 张本人照片全拍于很短的时间内，默认间隔只得到 1 个时段，切分间隔由学生定。
- **YOLO 分层**：这批照片进过 YOLO 训练或验证集的，"规则 + 检测框"必须按 `yolo_split` 分层报告，不和 VLM arm 混成一个数；规则流水线单列为参考组。
- **标签状态**：只有 `reviewed`（学生确认）一栏是证据，`provisional` 一栏只用来检查流程（暂定标签就是规则对真值框的输出，规则基线在这一栏按构造满分）。
- **指标**：单字母 top-1 + Wilson 区间、每类召回与混淆矩阵、开放集 AUROC、ECE、JSON 合法率、器材 F1（参考）；开放名称命中率用学生冻结的同义词表或学生亲评，不用另一个 LLM 当评委。11 月只做小的描述性检查，不做非劣效或优效声明。

### 7.6 预先登记的目标，以及完整性规则

**学生的目标**（原话）：微调模型基本持平或超过 DeepSeek V4.1 Flash 这类强开源模型。把它写成预先登记的"先非劣效、再优效"目标，**结构由开发侧给出，所有数值由学生定**：

| 要登记的项 | 内容 |
|---|---|
| 对比双方 | 微调模型（S1，或达上线条件的 S3）对 V4.1-Flash 非思考档；在配对对照子集上 |
| 主指标 / 适用子集 / Δ / α / 单双侧 / 检验方法 / 样本量与功效 | 〔学生定〕；检验结构为配对差值的置信区间下界与 −Δ 比较；判定顺序固定：先非劣效，成立后再检验优效，不能事后换 |
| 登记位置 | 学生亲笔写的研究计划；日期和 bench 哈希写进实验记录本 |

非劣效目标只针对 V4.1-Flash 的非思考档；27B 仍是描述性比较；这个目标不能变成与主线 C 竞争的新主假设，是否纳入 Holm 校正由学生在计划里定。被砍的目标标"未执行"，不能悄悄从报告里删掉。

**完整性规则**：(1) 先冻结后比较，冻结后不改样本、标签、评分、子集、指标和 Δ。 (2) 结果照实报告，所有 arm 都列出，没跑成的写"缺失"和原因。 (3) 达标靠训练，不靠调 bench：不允许把 bench 样本或变体放进训练或蒸馏题目、用 bench 选提示词/检查点/超参。**已知的混杂**：蒸馏教师（DeepSeek）同时是评测对照之一，所以与 V4.1-Flash 的比较要同时报告"只用引擎标签"的臂和含蒸馏样本的臂，是否这样设计由学生在冻结前定。 (4) 口径谨慎，不外推成通用能力。 (5) 每个 API 基线都是某日期、某 `model` 字段的快照。 (6) Rule 8：文档里的网址只是评测方案的参考，写进论文或海报的参考文献要学生自己核对原始页面。

## 9. 数据计划

- **D1 合成数据**（主数据）：全部由带随机种子的代码生成，逐字节可复现。离开 Mac 的只有代码、训练包和（学生冻结后的）bench。
