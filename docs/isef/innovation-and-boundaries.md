# 创新点与边界（工程记录，不是研究计划）

> ISEF Rule 8：本文件是开发者的工程记录。研究计划、摘要、海报、论文和结论由学生本人从空白页写，
> 这里的表述只能作为想法来源，并在 Form 2A 里披露。

## 1. 项目一句话

一个完全离线的中学力学实验 AI 伙伴：拍一张装置照片，它认出实验，把这台装置变成可计算的物理孪生，
带学生先预测、再测量、边测边对照，数据出问题时用贝叶斯推断找出系统误差来源，并告诉学生下一次该测什么。

## 2. 自己的创新点（物理为主）

| # | 创新点 | 物理内容 | 计算机内容 |
|---|---|---|---|
| 1 | 误差物理孪生 | 12 个实验的前向模型，含转动惯量、绳子质量、遮光片宽度、弹性限度、调零方向、反应时间等系统误差的推导和仪器噪声模型 | 统一接口、线性参数解析积分的贝叶斯引擎 |
| 2 | 可辨识性图谱 | 课本标准方案在文献量级噪声下能否区分各原因；分开它们需要哪一次测量 | 蒙特卡洛贝叶斯最优混淆矩阵、期望信息增益 |
| 3 | 看图建模 | 装置构型决定实验类型和孪生参数 | YOLO 器材线索 + 本地视觉语言模型 + 一个澄清问题 |
| 4 | 物理引擎当老师 | 标签来自对含噪、学生式数据的逆推断（物理正确性可证） | 小模型 LoRA 微调，迁移到训练中没见过的实验 |
| 5 | 真实器材闭环 | 故障注入实验检验孪生预测（sim-to-real） | 自适应测量推荐 vs 固定方案的配对比较 |
| 6 | 探究式教学 | 实验前预测、误差与知识点关联、修正后复测验证 | 按阶段组装上下文、事实单 + 声明校验器、脚本兜底 |

## 3. 与格物论文的边界

格物：在文本物理题库上做解题辅导；9B 模型；代数沙箱和工具循环；投票；多个服务"合同"档位；用教师模型的解题轨迹做主要训练数据。

本项目：

| 方面 | 格物 | 本项目 |
|---|---|---|
| 任务 | 文本题解题 | 动手做实验：照片、真实测量数据、误差诊断、测量设计 |
| 物理从哪里来 | 模型推导 + 代数沙箱算数 | 确定性物理孪生和贝叶斯引擎算出全部数字，模型不算物理 |
| 工具 | 模型在循环里写代码调用沙箱 | 没有沙箱、没有工具循环；引擎结果以事实单形式交给模型 |
| 投票 | 有 | 无 |
| 主要训练数据 | 教师模型的解题轨迹 | 物理引擎标注的诊断与设计任务、你自己的照片、脚本化引导 |
| 模型 | 9B，LoRA r=32 | 4B 视觉语言模型，LoRA r=16，含图像任务 |
| 评测 | 题库准确率 | 物理 bench（诊断、测量设计、迁移到留出实验）+ 识别 bench（照片） |

**唯一借鉴**：蒸馏时教师"盲做"，只保留和可核验标准一致的输出，训练提示里保留教师当时看到的指令。
我们的"标准"是物理引擎的判定（等价类内的最可能原因），蒸馏条数不超过 5,248。

## 4. 产品输出的约束（来自用户）

- 产品运行时只用自己的基础模型（Qwen3.5-4B + 自己训练的适配器）和自己的物理代码，不调用任何其他模型或 API。
- API 模型（DeepSeek V4.1 Flash 等）只作为评测对照组和离线蒸馏教师。
- 目标：在两个 bench 上达到或超过 DeepSeek V4.1 Flash 这类强开源模型。这个目标在冻结测试集之前由学生写定，结果如实报告。
