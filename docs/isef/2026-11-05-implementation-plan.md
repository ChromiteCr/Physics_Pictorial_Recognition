# 实验侦探（Lab Detective）：ISEF 升级实施计划

## Context

**为什么要改**
- 项目上一轮没有获奖。老师的意见：技术上要在大模型或视觉模型上真正动刀；实践和项目闭环是可以提前拿到的分。
- 旧系统（YOLO + 规则 + 手填读数 + GLM 讲解）和已有工作 PhysicsAssistant 几乎同构，而且只会给出"相对误差 < 15% 算验证成功"这种结论。

**要做成什么**：一个完全离线的力学实验 AI 伙伴（"实验侦探"）。
- 拍照认出装置，变成物理孪生；带学生先预测、再测量、边测边对照；找出系统误差来源，数据分不开就直说，并推荐最能分开各原因的下一次测量；依据事实单讲解并关联知识点。
- 背后是贝叶斯物理引擎。它同时负责生成训练标签，用来 LoRA 微调 Qwen3.5-4B；另有不超过 5,248 条经引擎一致性过滤的蒸馏样本。
- 科学部分有三条主线（§3），另外加上学生本人在真实器材上做的故障注入闭环。

**已定的约束（来自学生的回答）**
- 时间：11/15 交带结果的完整项目，11/14 前必须有结果；11/6 起可以 24 小时工作。
- 模型：产品用微调后的 4B；Qwen3.8-27B 只当对照组。系统内不调用任何外部 API，API 模型只在实验里当对照组、在离线构建数据时当蒸馏教师。
- 分工：课堂使用由学生处理，开发侧只管技术开发；GPT 跑在另一台低性能机器上，没有算力，只做审查和独立重写，材料靠学生转交。
- 资源：5090 有 SSH，不保证能连上 Hugging Face；self_captured 里的照片是学生本人拍的、里面没有人；本机我们启动的所有进程合计不超过 24 GB。

**完整设计**：理由、合规细节和风险表在 `docs/isef/2026-10-31-isef-upgrade-design.md`；模块与接口在 `docs/ARCHITECTURE.md`；规划阶段的 AI 记录在 `docs/isef/isef-upgrade-logs/`，填 Form 2A 时要用。

**ISEF Rule 8**：这份是工程计划。研究计划、摘要、海报、论文和结论都由学生亲笔写，阈值由学生定，AI 不提供文献。

## 1. 已定的决定

**来自学生的回答**：见上面"已定的约束"。

**开发侧替学生定的默认值**（不同意直接说）
1. **文献参数表**：来源和页码一律留空，所有数值先标"假设"。学生自己检索、读过之后再补来源，改标"文献"。
2. **留出实验**：训练侧与留出侧的划分按 `labsim` 注册表的 `held_out`；物理组件层的新组合默认留出，做迁移测试。留出实验数量少时跨实验符号检验功效很低，Phase 2 增加。
3. **单摆（或其他留出装置）的真实实验**：每次都做三项追加测量——模型建议的、留出孪生引擎的 EIG 选择（两者不同时才做）、一次重复。主线 B 的真实检验只用课内实验，留出装置单独报告。
4. **照片**：识别评测用学生本人拍的照片；视频帧和网图都不用于评测。识别准确率的正式评估放到 Phase 2。
5. **服务器下载**：优先 ModelScope，其次镜像站；代码用 scp 传，不靠 GitHub。权重始终拉不到时改用 Mac 兜底训练，单独登记为 "S1-mac"，不冒充 S1。
6. **课本方案**：默认按人教版，仪器配置可切换（光电门、打点计时器、秒表）；由学生审核物理卡时最终确认。
7. **27B 的运行时间**：产品冻结之后的夜里单独跑，期间 Mac 上不跑开发任务。
8. **蒸馏教师**：DeepSeek（学生提供 key，写入 `~/.config/ppr/keys.env`）；没有 API 的教师（Hy4）走提示词包导出/导入。教师同时是评测对照之一，所以与它的比较要报告"仅引擎标签"臂（见设计文档 §7.6）。

## 3. 三条科学主线

具体阈值由学生在研究计划里定。

- **A 可辨识性图谱**：作为预先规定的定量成果交付——课本标准方案下哪些原因根本分不开；哪一次测量能把它们分开。真实实验用来检验图谱的预测效度。
- **B 闭环里的下一次测量**（确认性）：EIG 自适应选择对"最佳固定追加测量"；模拟部分在高保真世界里做，真实部分用课内实验，都用配对 Wilcoxon。
- **C 模型迁移**（确认性，主要的机器学习主张）：闸门检验为 S1 对打乱标签对照（精确 McNemar）；总效应为 S1 对 3-shot 基线；双侧检验，零结果照样报告；top-1 在等价类上计算；跨实验用精确符号检验并如实写明局限。
- **对照**：K0 到 K6。**工程指标**：EC1 到 EC7。**评测基准**：物理 bench 与识别 bench（设计文档 §7）。

## 6. 不能跳过的闸门

**合规**
- 任何正式运行之前，必须满足三条：研究计划由学生亲笔写完、表格签好、物理卡审核完。
- AI 不写计划、摘要、海报、论文和结论，也不提供文献。
- 提交信息里不写任何 AI 的名字；AI 参与的部分在 AI_USAGE 台账里披露。
- 学生以外的任何人使用 app，需先有 SRC 书面裁定或 IRB 批准（设计文档 §12）。

**内存**
- 产品运行时约 6–9 GB（估计，以 E8 实测为准）。27B 只在夜里单独跑；跑之前先退出其他大模型程序、关掉自动加载、设置 `HF_HUB_OFFLINE=1`。
- 我们启动的所有进程合计不超过 24 GB；新任务启动前"当前用量 + 声明峰值"不超过 21 GB，超过 23 GB 时先停最简单的任务。

**torch 版本**
- Mac 上不升级，torch 只给 YOLO 用，训练和推理走服务器与 MLX。服务器上训练栈和推理栈各自固定在官方支持的版本。

## 7. 验证

**单元测试**（pytest，Mac CPU，每项几秒；全套 `python -m pytest -q -p no:cacheprovider`）
- 零故障数据还原理想定律；大幅故障呈现手推出来的特征；后验正确归一化；引擎校准；两原因 EIG 与解析解一致。
- 物理组件层镜像测试：与精选实验逐项一致。
- 转换器在随机小张量上往返一致，名称映射正确；服务器数据管线、打乱标签对照步数一致。
- 校验器能抓出故意写错的数字、单位和方向词；泄漏检查能抓出故意放进去的重复样本；同一份数据冻结两次哈希相同。
