## design
  - name: Lab Detective: engine-trained, fully offline diagnosis of systematic error in school mechanics labs, and the one measurement that settles it (continuation of Physics Pictorial Recognition)
  - one_line_pitch: A 'wrong' lab result is usually an accurate measurement of a slightly different experiment. Lab Detective is a fully offline lab partner that works out which hidden cause best explains a student's mechanics data (unbalanced friction, a mis-zeroed spring scale, a spinning ball), says plainly when the data cannot tell, and names the one extra measurement that would settle it. The Bayesian physics engine behind it also trains a 4-billion-parameter vision-language model with no human or API labels, and the project measures how much of that skill transfers to experiments the model never saw, as a fraction of the Bayes-optimal limit.
  - research_question: How close can a laptop-sized vision-language model, fine-tuned only on tasks labelled by a Bayesian physics engine and run fully offline, come to the Bayes-optimal limit set by the measurement protocol in naming the systematic cause behind school mechanics data and choosing the most informative next measurement, on experiments held out from training?
  ## hypotheses_or_criteria
    * RULE FOR EVERY LINE BELOW: bracketed numbers are proposals. The student restates each claim in his own words, chooses the final numbers and commits them in his signed research plan. The frozen test-set SHA-256 hashes are appended to the plan, dated, before any training or evaluation. Each arm has one pre-specified checkpoint. 'Bayes-optimal' always means 'Bayes-optimal under our simulator's assumptions'. A miss is reported as a miss.
    * C1 - CONFIRMATORY, SCIENCE (identifiability atlas, E1). Under each curriculum experiment's standard multi-point worksheet (as written in the student's textbook), simulated with literature-calibrated noise, at least one pair of modelled causes is robustly confounded in at least [4] of the 6 experiments. Robustly confounded means pairwise Bayes-optimal accuracy < [0.6] in all four sensitivity settings (fault-size priors x0.5 and x2; noise x0.5 and x2). For each confounded pair, one extra measurement from the menu lifts pairwise Bayes accuracy to >= [0.8]. Falsified if fewer than [4] experiments have a robust confound, or if some confound cannot be resolved by any single menu measurement. The old app's single-reading protocol is reported descriptively only, because its failure is nearly certain.
    * C2 - CONFIRMATORY, CLOSED LOOP (E3, E5). One extra measurement chosen by expected information gain (EIG) raises the engine posterior of the true cause more than one repeat of the last measurement, which is what students usually do. (a) Simulation: 840 closed-loop cases whose extra measurements come from the hi-fi simulator (it contains effects the engine never models), paired Wilcoxon signed-rank, alpha 0.05; the same test on labsim is reported as an in-model check. (b) Real apparatus: the student's own sealed fault-injection runs, where BOTH follow-ups are measured in every run in script-randomised order, paired Wilcoxon, n >= [24] runs. If fewer than [24] real runs exist at the analysis freeze, (b) is reported as pending and completed in Phase 2 with the same method.
    * C3 - CONFIRMATORY, PRIMARY ML (E4). On the 6 held-out experiments (720 cases), the engine-trained Qwen3.5-4B (S1, engine-target SFT) beats the untuned Qwen3.5-4B on top-1 cause accuracy (exact McNemar, two-sided alpha 0.05). Both arms get the identical prompt contract, experiment card, code-computed signature panel, candidate causes written as plain physical descriptions with no signature tags, JSON schema, greedy decoding and 512-token budget. The gain is also reported as a fraction of the engine's Bayes-optimal accuracy on the same cases, with an experiment-level cluster bootstrap. C3 is read as 'learned from engine labels' only if the shuffled-label LoRA control gains < [2] pp over the base on the same cases.
    * SECONDARY FAMILY (pre-registered, Holm-corrected, none is a headline claim). S-a transfer ladder, S1 vs base, on in-distribution, noise-shift, withheld-cause and hi-fi sets; pre-registered accuracy drop from in-distribution to hi-fi <= [10] pp. S-b S2 (expert iteration seeded from S1) vs S1 on the held-out experiments. S-c lower normalised EIG-regret of the model's next-measurement choice for S1 than base (Wilcoxon). S-d better calibration for S1 than base (Brier score, 15-bin ECE), and a false-alarm rate on clean data <= [10]%. S-e the best 4B is non-inferior to the untuned Qwen3.8-27B on a stratified 800-case subset (margin [3] pp) while using <= 1/4 of its peak memory. S-f verifier-flagged unsupported claims are <= [5]% for the tuned 4B and fewer than for both base models (McNemar); the verifier reaches precision >= [0.9] and recall >= [0.8] against the student's blinded audit. S-g on held-out experiments, S1 predicts each candidate cause's signature type more accurately than base; this is the mechanism of transfer. S-h engine honesty: >= [70]% of unmodelled faults are flagged 'cause not in my list'.
    * CONTROLS THAT MUST PASS BEFORE ANY RESULT IS INTERPRETED. K1 the oracle-in-prompt arm scores >= [98]%, showing the harness and parser work. K2 the leakage checker catches a planted duplicate. K3 swapped-table control: each case keeps its label but gets the data table of another case of the same experiment, and every arm must fall to within [5] pp of chance. This shows decisions come from the data, and replaces the earlier row-shuffle idea, since row order carries no information. K4 adapter-effect check: the converted Mac adapter changes the output on >= [90]% of the parity cases where the server adapter changed it. K5 no-panel ablation run on both base and S1, reporting what the levelling tool itself contributes.
    * WHAT THE UPGRADE MUST NOT CHANGE (TOST equivalence: the 90% CI of the paired difference must lie inside the margin). (1) The 4B's photo recognition on the people-screened, provenance-cleared image set plus the external CC set, within +/-[5] pp. (2) A fixed 300-item PhyX subset (MIT licence) of general physics, within +/-[3] pp.
    * ENGINEERING CRITERIA (pass/fail). EC1: every function works with networking off, and no external API is called inside the product. EC2: the product stack peaks at <= [8] GB; everything we run together never exceeds 24 GB (watchdog log); the 27B baseline, run alone, peaks at <= [22] GB. EC3, latency on the M4 Pro: engine diagnosis < 1 s; 4B diagnosis plus explanation median <= [15] s; photo recognition <= [10] s per photo of <= 1024 px. EC4: >= 99% of outputs are schema-valid. EC5: manual selection of the six curriculum experiments is reachable in <= 2 clicks from every screen and is never overridden. EC6: >= 95% identical top-1 between the server bf16 adapter and the Mac 4-bit build on 200 parity cases. EC7: the fixed 'relative error < 15% = verified' rule is gone everywhere, replaced by an uncertainty-normalised z agreement.
    * EXPLORATORY (no confirmatory claim). (1) Fix-and-verify predictions on >= [6] real runs. (2) The measured zero shift of the school's spring scales between vertical and horizontal use; the literature search found no value for it. (3) Near- vs far-transfer breakdown per held-out experiment. (4) P1 recognition results (candidate sets, one clarifying question, minimal pairs), reported per source group as small-n.
  - product_experience: STUDENT (laptop tier, fully offline; Chinese UI with an English toggle for the booth)
1. Open Lab Detective with networking off. There are two doors: 'Pick my experiment' or 'Identify from photo'. The six curriculum experiments are one click away on every screen, and a manual choice is never overridden.
2. Photo path.
- YOLO draws boxes and the student corrects them on the existing canvas. The existing rules decide when they can.
- On a tie or an unknown setup, the local 4B model sees the photo, downscaled to <= 1024 px, with numbered boxes. It returns one of the six experiments or 'other: <name>', plus the cues it used ('string over a pulley to a hanging mass', 'track tilted').
- The proven cart+track tie is settled by one question: 'What will you measure? Time over a marked distance / acceleration with a hanging weight / speed at the bottom of the slope.'
- P1: a small candidate set is shown instead of a single guess.
3. 'Other experiment'. The app says it has no physics model for '<name>'. The student picks the variables and the expected relation from a short menu: proportional, linear, inverse, square or power (P1: pre-filled from the photo). Code computes the same signature panel used everywhere, and the tuned model proposes suspects and a next measurement. Every later output is labelled 'AI estimate - not physics-verified'.
4. Predict first (optional, predict-observe-explain). The student taps the suspect he expects. The choice stays on the device.
5. Enter a multi-point table, e.g. extension for 5 loads, acceleration for 5 hanging masses, or final speed for 3 heights. Instrument resolutions come pre-filled from the teacher's profile. A single reading is still accepted, with a note that one point cannot separate suspects.
6. Agreement meter, e.g. 'k = 24.1 +/- 0.6 N/m; z = 2.4: in tension'.
- Bands: consistent / in tension / inconsistent.
- The relative error is still shown, but the fixed 15% rule is gone.
7. Suspect board: 4-6 cards plus 'Just noise' and 'Cause not in my list'.
- Each card shows a friendly name, the physics name, the data signature it predicts and a live probability bar, e.g. 'Sticky track = friction not balanced: the a-F line crosses below zero'.
- Ghost curves: each top suspect's best-fit curve is drawn through the student's points.
8. One-more-measurement card.
- It names the single most informative next measurement and its lab minutes.
- Before the student measures, it shows each top suspect's predicted result ('Sticky track: about 0.35 m/s^2; Heavy hanger: about 0.52 m/s^2'). He may type his own prediction first.
- He measures, enters the value and the bars move, for up to 3 rounds.
- If no measurement on the menu can separate the last suspects, the app says so and explains why.
9. Verdict and fix-and-verify.
- The culprit is shown with a size interval, a quantitative fix and the predicted re-run result ('after re-zeroing, the intercept should be 0 +/- 0.03 N').
- The re-run either confirms the culprit or reopens the case.
10. Explanation.
- Up to 120 words, written by the local model from the engine's fact sheet.
- Every number, unit, direction word and named cause is checked. The model gets one rewrite; after that a fixed template is used.
- In scripted mode only templates appear.
- Curated 'how to reduce this error' tips follow, matching the curriculum requirement to analyse errors and propose ways to reduce them.
11. Export the table, plots, verdict and the deciding measurement into his own report.

TEACHER
1. Once: set instrument profiles (spring-scale division and range, ruler, cart mass, track length, photogate flag width). Per lesson: choose the experiments and switch off causes that do not apply to the school's kit. The 'speed computed from the height' method check is off by default.
2. Scripted mode (template text only) is the default and is required for every lesson. Assessment mode (P1) shows the evidence and probability bars but hides the verdict.
3. Protocol view (P1): a heat map from the atlas of which causes today's worksheet cannot tell apart, plus the one protocol change that fixes most of them (e.g. 'add a zero-hanging-mass run').
4. Fault-library viewer: each cause's physics, data signature, noise model and source.
5. Practice challenge (P1): the software plants a hidden fault in a virtual run, and groups find it with the fewest measurements.
6. Lessons are ordinary teaching. Nothing is logged or collected, and nothing enters the ISEF project unless a later IRB-approved study runs (Phase 3).

JUDGES AT THE BOOTH (English build, offline, frozen)
1. Judge Challenge (P1).
- The judge draws one of 12 paper sabotage cards and picks a fault size.
- The hi-fi simulator, which contains effects the engine never models, produces a realistic data table.
- Lab Detective, on the 4B laptop tier, must name the culprit within 3 extra measurements, or say which pair it cannot separate and which measurement would.
- Precomputed scenarios are the fallback.
2. The spinning ball.
- The old app said 'error 29%, not verified', and the student blamed friction.
- Lab Detective shows that friction, rotation, slant length used as height and a flag-width error all fit the data at one angle. It asks for one run at a different angle; the ratio does not change, so rotation wins.
- Measuring the ball and the rail gap then explains why the share of energy in translation is even below 5/7.
3. Poster figures: the atlas heat maps, the transfer ladder as a fraction of the oracle, and the paired real-run result.
  ## technical_components
    [0]
      - name: labsim: executable physics twins of 12 mechanics experiments with curriculum fault libraries
      - what: - numpy forward models of each measurement protocol. All share one closed signature vocabulary: y-offset, x-offset, slope scale, bend at high x, scatter too large, scatter too small, drift with trial order, none.
- Training experiments (the six in the app's registry): friction, average speed, Hooke's law, Newton-2 with hanging mass, momentum with two carts, energy on an incline.
- Held-out experiments, used only as graders and never in training. Classified in advance as near transfer: inclined-plane friction, Atwood machine, free fall. Far transfer: simple pendulum g, horizontal projectile, lever balance.
- Each experiment has 4-6 causes, always including 'random error only'. Every cause carries a plain physical description, a signature tag, a fix and a source tag ('literature' or 'assumption'). Examples:
  - Newton-2: friction not balanced or over-balanced; hanging mass not << cart mass, with relative error (m+m_e)/M; string not parallel to the track.
  - Hooke: total length recorded instead of extension; hanger mass omitted; ruler zero offset; beyond the elastic limit.
  - Friction: scale zeroed vertically then used horizontally; upward pull angle; accelerating pull.
  - Energy: slant length used as height; rolling friction; flag-width error; rotational energy. A solid ball on a flat surface keeps 5/7 of the energy as translation; on two rails the contact radius r < R lowers this to 1/(1 + (2/5)(R/r)^2). Also a 'speed computed from the height' circular-method check, off by default and enabled by the teacher.
  - Momentum: track not level; friction between the gates; mass mis-entry; common flag-width scale.
  - Average speed: distance measured front-to-rear; cart not released from rest; slope too steep for manual timing.
- One cause per training experiment is withheld from training and from the training candidate lists. This is the 'new cause in a known experiment' rung.
- Noise uses literature values where they exist: manual start-stop interval N(0, 0.10^2 s^2); single-action bias 0.11 s with sd 0.07 s; resolution d/sqrt(12); ruler +/-1 mm; a photogate-bias case of about 5.7%. Where no value exists (spring-scale zero shift, parallax), a wide prior is used and flagged 'assumption'.
- Menus of 3-6 feasible extra measurements per experiment, each with estimated lab minutes and a simulated outcome.
- A one-page physics card per cause (formula, signature derivation, source tag) is generated from the code for the student's review.
      - novelty_vs_prior_art: The physics of each cause comes from textbooks or teacher literature (e.g. He 2016 on (m+m_e)/M; Kok & Priemer 2023 on rotational energy) and is not claimed as new. The verified search found no executable, tested library of systematic-error hypotheses with literature noise for school mechanics experiments that serves as the shared ground truth for diagnosis, protocol audit and model training. CNKI was not searched systematically; the student checks it before claiming novelty.
      - feasibility_and_memory: - Pure numpy, < 0.5 GB, milliseconds per simulated dataset.
- About 1.5k lines (estimate), written by the coding assistant 10-31..11-03.
- Seconds-long analytic unit tests: zero-fault data must recover the ideal law, and large faults must show the hand-derived signature.
- Independent checks:
  - the second assistant re-implements the Newton-2 and energy forward models and one two-cause EIG case from the written physics spec (a differential test, logged);
  - the student reviews every training-experiment physics card on 11-07, before training;
  - the student hand-codes one fault model himself (Hooke ruler-zero offset).
- Mechanics only, so every cause can be derived on a whiteboard in the interview.
      - priority: P0
    [1]
      - name: Bayesian diagnosis engine with an honest 'cause not in my list'
      - what: - Computes a posterior over {random error only, cause_1..cause_K, none of these}.
- Marginal likelihoods: closed form (Bayesian linear-Gaussian) when a fault is linear in its parameters (offsets, scale factors); grid quadrature otherwise.
- Nuisance parameters (true k, mu, g-scale, cart mass) are marginalised on grids with weakly informative priors.
- A posterior-predictive misfit statistic, calibrated on simulation to a fixed false-alarm rate of [5%], triggers 'cause not in my list'.
- Uncertainty-normalised agreement z = (measured - predicted) / combined standard uncertainty. Proposed bands: consistent |z| < 2, in tension 2-3, inconsistent > 3. The classic relative error is still shown.
- Emits a fact sheet for the explainer, the verifier and the UI: numbers, units, signs, top causes, counterfactual ghost curves, the fix and the predicted re-run value.
- Registry v2 replaces physics.py's single-reading forms with multi-point tables and instrument profiles; single readings are still accepted.
      - novelty_vs_prior_art: The methods are classical: model-based diagnosis (de Kleer & Williams 1987), model discrimination (Box & Hill 1967), Bayesian model comparison in intro labs (Blais 2020). New is automatic, real-time use over a curriculum fault library, evaluated against an oracle and on real runs. Replacing pass/fail with an uncertainty-normalised comparison follows physics-education arguments the student should find and read for himself.
      - feasibility_and_memory: - Vectorised numpy on the CPU; estimate 1-10 ms per diagnosis and < 0.3 GB; runs inside the product on the Mac.
- Unit tests: planted-fault recovery, posterior normalisation and an Occam check.
- Written 11-02.
      - priority: P0
    [2]
      - name: Expected-information-gain advisor and closed loop
      - what: - For each menu item, a Monte Carlo EIG on the posterior over causes (about 100-256 simulated outcomes), optionally per lab minute.
- It recommends the best item, says which suspects that item separates, and shows each top suspect's predicted outcome before the student measures.
- It takes the new reading, updates the posterior and repeats for up to 3 rounds. When no menu item can separate the remaining suspects, it says so plainly.
- A simulated-student loop drives E3, comparing EIG, EIG per minute, repeat, random choice and a fixed textbook extension.
- Real-run support for E5: every run records BOTH the EIG follow-up and a plain repeat, in an order taken from a committed random schedule.
- The same code picks the single clarifying question in recognition (P1).
      - novelty_vs_prior_art: Choosing measurements by EIG is old (GDE 1987; BOED reviews; NIST optbayesexpt 2021), and BoxingGym (2025) reports that LLMs struggle at EIG-style design. Not found: EIG advice for school mechanics labs, tested in a real physical closed loop against students' usual default of repeating the same measurement.
      - feasibility_and_memory: Estimate 0.1-1 s per recommendation on the CPU; negligible memory. Written 11-02.
      - priority: P0
    [3]
      - name: Identifiability atlas: the Bayes-optimal limit of school protocols
      - what: - Monte Carlo Bayes-optimal confusion matrices for each of the 12 experiments under these protocols:
  - P0, single reading (the old app);
  - P1, the standard multi-point worksheet as written in the student's textbook (he confirms it);
  - P1 plus 1 EIG measurement, and P1 plus 2;
  - controls: P1 plus 1 repeat, and P1 plus 1 random item.
- Outputs: pairwise confusability; the measurement that resolves each confused pair; sensitivity to fault-size priors and noise (x0.5, x2).
- It also provides the oracle ceiling that every model arm is normalised against, and the teacher's protocol view.
- Worked examples the student can derive by hand:
  - Energy, with only the release height varied at one angle: four causes all give a constant KE/PE ratio below 1. They are slant length used as height (ratio sin theta), rolling friction (1 - mu cot theta), rotational energy (5/7, lower on two rails) and a flag-width error (k^2). One change of angle separates the first two from the last two; measuring the ball and the flag separates the last two.
  - Hooke: a hanger mass left out of the force, a ruler zero offset and a recorded total length all appear as a nonzero intercept of the F-x line, because with a free slope an x-offset is indistinguishable from a y-offset. Only their typical sizes differ. The atlas measures how often the worksheet confuses them and names the separating measurement (weigh the hanger; read the unloaded spring).
      - novelty_vs_prior_art: Not found in the literature searched. This is the project's physics-education result, and it stands even if the ML part fails.
      - feasibility_and_memory: Estimate 1-3 CPU-hours with 4 workers on the Mac, < 2 GB, run on 11-07 while no model is loaded. Before 11-06 it runs only at debug size (n = 20 per cell), with outputs discarded.
      - priority: P0
    [4]
      - name: Signature panel and closed signature vocabulary (the levelling tool)
      - what: - Code computes the panel for any experiment card (law in linearised form y = f(x), variables, units, instrument resolutions) and data table:
  - fit of the ideal law with a free scale: slope ratio to ideal and its z;
  - intercept z;
  - curvature z (quadratic term);
  - residual scatter against expected instrument noise (chi^2/dof, too large or too small);
  - runs test and drift against trial order;
  - for conservation experiments, the before/after ratio with its uncertainty.
- The same vocabulary is used by the engine's cause tags, the model's output and the UI's suspect cards.
- Every arm (base, tuned, 27B, API, classical) receives the identical panel, so a gain cannot come from the fine-tune learning arithmetic. A no-panel ablation measures what the panel itself contributes.
- In the open-set product path the same code analyses any experiment once the student picks its relation family.
      - novelty_vs_prior_art: Standard statistics used in a tool-integrated-reasoning pattern (PAL, ToRA). Not claimed as new; its role is to make the comparisons fair.
      - feasibility_and_memory: numpy, milliseconds. About 300 lines (estimate), written 11-03.
      - priority: P0
    [5]
      - name: Engine-verified fine-tuning of Qwen3.5-4B: S1 engine-target SFT plus the shuffled-label control (the model upgrade)
      - what: - Adapter: bf16 LoRA, r=16, alpha=32, dropout 0.05, on language-model linear layers whose PEFT names map one-to-one to mlx-vlm's qwen3_5 modules. Start with full-attention q/k/v/o and MLP gate/up/down; add the Gated-DeltaNet projections only if the converter's name-map test passes.
- Frozen: vision tower, embeddings, lm_head. Non-thinking chat format; loss on assistant tokens only.
- Input: experiment card; candidate causes as plain physical descriptions, with no signature tags; data table of 1-8 rows (single readings included); signature panel; measurement menu.
- Output JSON: short evidence; the data's signature; each cause's signature type and probability; p(none of these); the next measurement with the expected result under the top two causes; the z verdict; an explanation of <= 80 words, in Chinese or English (50/50).
- 20% of examples are cause-proposal tasks: propose up to 6 causes as (variable, signature type, description).
- S1 targets are written by the engine: posterior rounded to 0.05, the argmax-EIG item, the true signature tags, and a templated explanation with 3 paraphrases per slot.
- Anti-shortcut measures: cause IDs and their order randomised; magnitude priors overlap.
- Shuffled-label control: identical prompts, steps and seed, with cause labels permuted within each experiment.
- Each run is time-boxed to <= 2 h; the example count is set from throughput measured in the first 10 minutes.
      - novelty_vs_prior_art: Simulator labels and rewards already exist for forward physics QA (Sim2Reason 2026), VLM world-building (PhysEvolve 2026) and physics code (RLVP 2026). Calibration-aware rewards (RLCR) and STaR/RFT are known. New here:
- the inverse task: the cause from noisy, student-style measurements;
- the engine posterior as a proper-scoring target;
- measurement design as an output;
- transfer measured on held-out experiments as a fraction of the Bayes-optimal oracle.
It also tests BoxingGym's finding within one domain.

- Estimates: S1 1-2 h; the control 1-2 h, run in the evening.
- Adapter about 65 MB (estimate).
- Tooling: Unsloth, falling back to ms-swift, then plain PEFT/TRL.
- If the sm_120 stack fails, a reduced S1 is trained overnight on the Mac with mlx-vlm (estimate 6-10 GB, never alongside the 27B).
      - priority: P0
    [6]
      - name: S2 expert iteration seeded from S1 (S3 GRPO later)
      - what: - Merge S1 into the bf16 base, then sample 8 answers per prompt (temperature 0.8) on about 3k fresh training-experiment prompts.
- Sampling uses vLLM serving the merged model, because vLLM LoRA support for qwen3_5 is unconfirmed; batched HF generate is the fallback.
- Reward R = format gate x (0.5 x (1 - 0.5 x ||p - q||^2) + 0.3 x EIG(chosen)/max EIG + 0.2 x verifier pass with coverage), where q is the engine posterior.
- Keep the best sample if R >= a pre-registered threshold, then train one SFT epoch continuing from S1.
- S3, GRPO on the same reward with a KL penalty to S2, is P2. It runs only if S1, S2 and all controls are finished and the GPU is idle before 11-10; otherwise it moves to Phase 2.
- Deployment rule (pre-registered, not a claim): the product ships S2 only if it beats S1 by >= [1] pp top-1 on the in-distribution validation split with no faithfulness regression. Otherwise it ships S1.
      - novelty_vs_prior_art: Expert iteration / rejection-sampling fine-tuning (Yuan 2023; STaR, Zelikman 2022) with a bounded proper-scoring term (RLCR) and an engine-computed EIG term. The controlled SFT-vs-RFT comparison on held-out experiments tests the 'RL generalises, SFT memorises' prediction (Chu et al., ICML 2025) in a measurement-diagnosis domain.
      - feasibility_and_memory: Estimate 1-2 h of sampling plus 1 h of SFT on the 5090 (the merged 4B in bf16 is about 9 GB, plus KV cache). Seeding from S1 rather than the untuned base fixes the low-acceptance risk the judges found.
      - priority: P1
    [7]
      - name: Hi-fi misspecified simulator (test-only sim-to-real proxy)
      - what: - Adds effects the engine never models: pulley inertia and friction, rolling resistance, air drag, string mass, ex-Gaussian (skewed) timing noise and occasional transcription slips.

- Supplies the outcomes of the closed-loop continuations in C2a, so EIG is tested under misspecification.

    [8]
      - name: Evaluation harness: pre-registration, levelled baselines, controls, statistics, logs
      - what: - Seeded test sets are regenerated identically on the Mac and the server. Their SHA-256 hashes are compared and appended, dated, to the signed plan before any training; the files themselves are never uploaded.
- A leakage checker must catch a planted duplicate.
- One prompt contract for all arms: same card, candidates, panel and schema (constrained decoding where supported), greedy decoding, 512 new tokens. Thinking is off for local arms; API arms use their lowest reasoning setting (logged).
- Controls: oracle-in-prompt, swapped-table, unmodelled faults (two causes at once; a x10 transcription slip), clean data, and large obvious faults.
- Non-LLM references: gradient-boosted trees on panel features that predict the data signature, and a 20-line rule matcher. Both are given the oracle cause-signature tags.
- Statistics: exact McNemar; Wilcoxon signed-rank; Wilson and Clopper-Pearson intervals; paired and experiment-level cluster bootstrap (10,000 resamples); TOST; Holm; mixed-effects logistic regression as a sensitivity analysis; Brier; ECE with reliability diagrams; AUROC.
- Every local and API prompt and response is logged as JSONL with model id, build, settings and timestamp.
- Formal-run launcher: only the student starts formal runs. It asks for his name, writes a dated notebook stub, and refuses to run if the plan hash is missing.
      - novelty_vs_prior_art: Method, not novelty. It follows the measurement-first discipline of the Gewu paper the student studied: criteria fixed before runs, baselines levelled on grader, budget, tool and prompt, and positive controls. That paper reports a naive gain of about +22 pp falling to about +2 pp once levelled, which is why levelling is built in from the start.
      - feasibility_and_memory: CPU-light. About 800 lines (estimate), written 11-04.
      - priority: P0
    [9]
      - name: Fact-sheet explainer, claim verifier and scripted mode
      - what: - For registered experiments, the local model writes <= 120 words, using only the engine fact sheet.
- In open-set mode it writes from its own JSON, and the text is labelled 'AI estimate - not physics-verified'.
- A rule-based verifier (Chinese and English) extracts every number with its unit, every direction word (larger/smaller, 偏大/偏小), the named cause and the recommended measurement, and checks each against the fact sheet.
- It also requires coverage (the top cause, one numeric piece of evidence, the next measurement), so vague text cannot pass.

  - model_upgrade: WHAT IS MODIFIED
The language side of Qwen/Qwen3.5-4B. It is an official Apache-2.0 vision-language model with native image and video input. It uses the same qwen3_5 hybrid architecture (Gated DeltaNet + gated attention) as the student's Qwen3.8-27B, and its MLX 4-bit build is 3.06 GB.
- Adapter: bf16 LoRA, r=16, alpha=32, dropout 0.05, on language-model linear layers whose PEFT names map one-to-one to mlx-vlm's qwen3_5 modules.
- Full-attention q/k/v/o and MLP gate/up/down come first. The Gated-DeltaNet projections are added only if the converter's name-map test passes, because vLLM packs some of them (in_proj_qkv with in_proj_z, in_proj_b with in_proj_a).
- Frozen: vision tower, embeddings, lm_head. Non-thinking chat format; loss on assistant tokens only.
- Adapter size about 65 MB (estimate).

SKILL TAUGHT
Input:
- an experiment card: the law in linearised form, variables, units and instrument resolutions;
- candidate causes written as plain physical descriptions, with no signature tags, plus 'random error only';
- the data table (1-8 rows);
- the code-computed signature panel;
- a menu of 3-6 feasible extra measurements.
Output, in a fixed JSON schema:
- short evidence and the data's signature;
- for each cause, its predicted signature type and probability;
- p(none of these);
- the most informative next measurement, with the expected result under the top two causes;
- the z verdict;
- an explanation of <= 80 words in Chinese or English.
In 20% of examples the cause list is withheld, and the model proposes up to 6 causes as (variable, signature type, description).

DATA SOURCE
- About 20,000 prompts; the final count is set by measured throughput.
- Generated on the rented GPU server by seeded labsim code, from the six curriculum experiments only.
- Labelled by the Bayesian engine: the posterior rounded to 0.05, the argmax-EIG menu item, each cause's signature tag, and a templated bilingual explanation.
- One cause per curriculum experiment, and all six held-out experiments, never appear in training.
- No human labels, no frontier-API outputs, no student data. Only code is uploaded.

TRAINING
- S1, engine-target SFT (P0, the primary arm): one time-boxed run (<= 2 h or 2 epochs) with one pre-specified checkpoint.
- Shuffled-label control (P0): the same prompts, steps and seed, with cause labels permuted within each experiment.
- S2, expert iteration (P1): sample 8 answers per prompt from the merged S1 model on about 3k fresh training prompts. Keep the best one if reward R >= a pre-registered threshold, where R = format gate x (0.5 x (1 - 0.5 x ||p - q||^2) + 0.3 x EIG(chosen)/max EIG + 0.2 x verifier pass with coverage) and q is the engine posterior. Then train one SFT epoch continuing from S1.
- S3, GRPO on the same reward (P2): only if the GPU is idle before 11-10; otherwise Phase 2.
- Tooling: Unsloth, falling back to ms-swift, then plain PEFT/TRL.
- Weights, thresholds, step counts and the deployment rule are committed before training.

COMPUTE LOCATION
- Rented RTX 5090 (32 GB). bf16 LoRA of the 4B needs about 10 GB VRAM per Unsloth's Qwen3.5 table. The table does not state a sequence length, so this is verified in the first run. Training in bf16 avoids Unsloth's warning against QLoRA for this family.
- The environment is set up on 11-06 with no data: PyTorch for CUDA >= 12.8 (needed for sm_120), transformers >= 5.2, flash-linear-attention and causal-conv1d.
- Evaluation and S2 sampling serve merged models with vLLM's qwen3_5 class (its LoRA support is unconfirmed), falling back to batched HF generate.
- Throughput is measured in each job's first 10 minutes, and every job is time-boxed.
- If the stack fails, a reduced S1 is trained overnight on the Mac with mlx-vlm (estimate 6-10 GB, nothing else loaded).

DEPLOYMENT PATH
1. The adapter (about 65 MB) goes to the Mac via a private Hugging Face repo or direct download.
2. A PEFT-to-MLX converter renames keys, transposes lora_A/lora_B and sets scale = alpha/r.
3. mlx_vlm.server --adapter-path serves it on lmstudio-community Qwen3.5-4B-MLX-4bit, with JSON schema, token logprobs and thinking off by default. This server is needed because LM Studio cannot load adapters.
4. A 200-case parity gate (>= 95% identical top-1) and the adapter-effect check must pass.
Fallbacks: mlx-vlm's dequantise-add-requantise fuse into the 4-bit model (never mlx_lm.fuse, which drops the vision tower); or ship v1 with the untuned 4B plus the engine and swap the adapter in at v1.1.
In the product, the engine supplies the probabilities for the six curriculum experiments and the tuned model writes checked explanations. For any other experiment, the tuned model's diagnosis is shown, labelled 'AI estimate'.

HOW IT IS MEASURED
- Primary (C3): top-1 cause accuracy on 720 held-out-experiment cases, S1 vs the untuned 4B, exact McNemar, also reported as a fraction of the Bayes-optimal oracle. It counts only if the shuffled-label control gains < 2 pp.
- Ladder (secondary, Holm): in-distribution, noise-shift, withheld-cause, hi-fi misspecified world, and near- vs far-transfer held-out experiments. Also S2 vs S1, EIG-regret, Brier/ECE, per-cause signature accuracy, recall@6 of proposed causes, faithfulness, and non-inferiority to the untuned 27B.
- References, all under the identical contract: engine and oracle; GBT and the rule matcher with oracle tags; the 3-shot in-context base; no-panel ablations; two frontier APIs.
- Must not change (TOST): photo recognition within +/-5 pp; PhyX-300 within +/-3 pp.
- Deployment: Mac/server parity, memory and latency.
- Stated in advance as 'no upgrade': S1 not better than base on the held-out experiments, or better only in-distribution.

WHY THE 4B, NOT THE 27B
- bf16 LoRA of the 27B needs about 56 GB, more than the card's 32 GB.
- Unsloth advises against QLoRA for Qwen3.5, and a bnb-4bit-trained adapter on the MLX affine 4-bit base is untested.
- The 27B alone already takes 18.5-21 GB of the 24 GB cap, so it cannot run beside the app.
- The 4B fits 8 GB school laptops.
The 27B stays the zero-shot generalist that the 4B specialist is compared against on the same Mac.

CONSIDERED AND NOT ADOPTED
- Counterfactual vision tuning on the 809 images (only 3 source videos); moved to Phase 2.
- The 24-family simulator.
- 9B GRPO as the headline.
- Distilling an API teacher.
- 27B QLoRA.
- Letting the VLM read gauges (MeasureBench: the best model reaches 30.3% on real images), so readings stay manual.
