# 02 只有你能做的决定

这份清单只列**要你拍板的事**和每件事要考虑什么，**不给答案**。代码和文档里出现的数值都是占位默认值，
不代表推荐；你定下来以后告诉开发者改成你的值，并把它写进你亲笔的研究计划（附日期）。
每一项都写了"在哪里"，方便你找到占位值。

建议的顺序：先定"保留哪些主张"，再定每条主张的阈值和样本量，最后定真实实验和训练的细节。
所有"冻结之前要定"的事，冻结以后就不能再改；要改只能作废、写 Addendum、出新版本、全部重跑。

---

## 一、保留哪些主张，哪些是确认性的

- [ ] **每条主张留不留，算确认性还是描述性。**
  候选：可辨识性图谱（主线 A）、自适应下一次测量 vs 最佳固定测量（主线 B）、模型迁移到留出实验（主线 C）、
  和 DeepSeek-V4.1-Flash 的比较、和 27B 的比较、通用物理能力不退化（PhyX）、真实器材闭环（E5）、单摆的"其他实验"通道。
  - 要考虑：每条主张要多少时间、算力和样本才有意义；确认性主张越多，多重比较的代价越大；
    砍掉的主张要写"未执行"，不能悄悄消失；零结果和负结果同样要报告。
  - 在哪里：设计文档 §4、§7、§16；实施计划 §3。
- [ ] **主指标：每条确认性主张只能选一个。**
  - 要考虑：等价类上的 top-1、真实原因的后验概率、log score、Brier 各自回答的问题不同；
    等价类怎么合并（图谱判为分不开的原因合成一类）也要在冻结前定。
- [ ] **显著性水平、单侧还是双侧、哪些检验放进同一个 Holm 校正族。**
  - 要考虑：单侧检验只在方向事先完全确定时才站得住；校正族越大越保守；描述性分析不进校正族。

## 二、每条主张的阈值

- [ ] **图谱："分不开"和"分得开"的判定线，以及每对原因的模拟样本量。**
  - 在哪里：`lab_detective/atlas.py` 的 `atlas_table(confused_below, separable_at)`（E1 用，告诉开发者改成你的值）；
    真实实验随机表里的图谱检查在生成随机表时用 `--atlas confused_below=… separable_at=… n_per_cause=…` 设定。两处要一致。
  - 要考虑：判定用的是 Wilson 区间的上界和下界，样本量越大区间越窄，同一条线下"部分可分"的会更少；
    样本量受 Mac 上的计算时间限制，先实测速度再定；故障幅度和噪声的 ×0.5、×2 敏感性分析也用同一条线。
- [ ] **一致性分档（|z| 的分界）和"原因不在我的清单里"的判据。**
  - 在哪里：`lab_detective/facts.py` 的 `band_of`（一致 / 有张力 / 不一致）和 `not_in_list`（失配 p 值的界线）；
    真实实验分析里同一个判据是分析规则的 `misfit_alpha`（`--analysis misfit_alpha=…`）。
  - 要考虑：界线越松误报越多、越紧漏报越多；"不在清单"在干净数据上的误报率应该接近你定的界线，可以用 E2 的干净集检查。
- [ ] **对照 K0 到 K6 的通过线。** K1（答案放进提示时要接近满分，"接近"是多少）、K3（换表后要降到机会水平，等价区间多宽、
  样本量多大）、K6（引擎校准的 ECE 上限）。
  - 要考虑：这些是"评测链路没坏"的闸门，线定得太松就失去意义；没通过时整套结果都不能解读，要事先写好怎么处理。
- [ ] **工程指标 EC1 到 EC7 的阈值**：峰值内存、诊断延迟、照片识别耗时、JSON 合法率、Mac 与服务器的一致率等。
  - 在哪里：设计文档 §4"工程指标"。要考虑：按开发阶段的实测值来定，在 E8 之前定死。
- [ ] **上线哪个模型（S1 还是 S3）的规则。**
  - 在哪里：设计文档 §6。要考虑：规则必须在 E5 开始之前定死，不能看了真实实验的结果再换。

## 三、和 DeepSeek-V4.1-Flash 的比较

- [ ] **对比的是哪一档。** 设计里主比较是它的非思考档，思考档只当天花板参考。
- [ ] **非劣效 margin Δ、α、单侧还是双侧、主指标、用哪个子集、用什么检验。**
  - 在哪里：设计文档 §16.6 的表格（每一格写着〔你定〕）。
  - 要考虑：Δ 和样本量互相制约，n 只有几百时 Δ 太小功效不够，功效计算由你自己做；
    判定顺序固定为先非劣效、再优效；输出不是合法 JSON、超时、拒答怎么计分（算错还是剔除）要事先定；
    每次 API 调用都是某个日期的快照，要记下返回的 `model` 字段。
- [ ] **API 预算上限和样本数。**
  - 要考虑：设计里每个 API 基线不超过 600 个合成样本；发出去的只能是合成数据或你确认过的无人像照片。

## 四、样本量（在算力范围内）

先让开发者实测每一步的速度，再在下面这些数里取舍。每个数都是"冻结之前定"。

- [ ] **图谱**：每对原因的模拟份数（设计里写的是 2,000 以上，按实测速度调整）。
- [ ] **引擎有效性 E2**：同分布、噪声偏移、留出原因、干净、未建模、高保真各多少。
- [ ] **模拟闭环 E3**：总例数，以及在高保真世界和模型内世界是否都跑。
- [ ] **迁移 E4**：每个留出实验多少例；验证集多少（只用于早停）。
  - 要考虑：跨实验的精确符号检验在留出实验只有 6 个时，必须全部提升才可能显著，这是"实验个数"的限制，不是"每个实验样本数"的限制。
- [ ] **训练数据**：每个任务生成多少条，程序化任务族占多少。
  - 在哪里：`python -m lab_detective.training.generate` 的 `--n-diagnose`、`--n-design`、`--n-explain`、`--n-knowledge`、
    `--generic-frac`、`--design-generic-frac`。要考虑：服务器上一次训练的时间上限（server/README §6）和吞吐探针的结果。
- [ ] **蒸馏**：用不用、用哪个教师（DeepSeek、Hy4）、各多少条。总数上限 5,248 是设计定死的，不能超过。
  - 要考虑：蒸馏样本只保留和物理引擎判定一致的回答；教师用量和费用要先估。
- [ ] **27B 子集**：先计时 10 例，再按一晚能跑完的量定。**PhyX**：至少 1,500 题，具体多少按服务器时间定。
- [ ] **识别 bench（11 月只做描述性检查）**：用你拍的多少张照片；"未知"和"其他实验"怎么计分。

## 五、真实器材实验（E5）

工具包在 `lab_detective/fieldkit/`，用法见 `06_真实实验工具包.md`。下面这些要在**生成随机表之前**定，
因为随机表一旦生成，它的哈希就要写进计划。

- [ ] **做哪几个实验。** 默认胡克定律、摩擦力、单摆；没有摩擦力的器材时换成牛顿第二定律。
  - 在哪里：`schedule build --experiments`。要考虑：实验室能用的器材、两次实验课的时长、换装置的时间。
- [ ] **每个实验做哪些条件、用多大的幅度。** 每个实验是"不设故障 + 3 种故障"。
  - 在哪里：`lab_detective/fieldkit/catalog.py` 里每个实验的 `recipes`（动作文字和幅度选项）。
  - 要考虑：幅度要落在引擎对这个原因设定的先验范围里；会损坏器材的故障一律不做（弹簧超过弹性限度只在模拟里做）；
    每个实验最好有一对图谱判为分不开的条件（生成随机表时会打印提示：胡克定律和牛顿第二定律的默认条件里，
    最难分开的一对目前只是"部分可分"，要不要换条件由你决定）。
- [ ] **哪些故障由成年人按密封卡设置（盲），哪些只能你自己设置（未盲）。**
  - 要考虑：卡片上已经标了谁来设置；未盲的运行要不要在分析里单独列一遍；学生能看出来的成年人设置也算未盲。
- [ ] **重复次数和实验课次数。** 默认每个单元 2 次重复、2 次课，共 24 次运行。
  - 在哪里：`schedule build --repeats --sessions`。要考虑：24 次时每个实验只有 8 次，主线 B 的合并检验只有 16 对，功效有限。
- [ ] **分析规则**（会写进公开表、受哈希保护）。
  - 在哪里：生成随机表时用 `--analysis 键=值` 设定（例如 `--analysis wilcoxon_alternative=greater alpha=0.01`），
    键和占位默认值见 `lab_detective/fieldkit/schedule.py` 的 `ANALYSIS_SPEC_DEFAULT`；写错键或取值会直接报错。
  - 要逐项定的：主指标；主对比（信息增益推荐 − 最佳固定测量）；合并检验用哪些实验（默认只用课内实验，单摆单独报告）；
    Wilcoxon 的单侧还是双侧；两项测量恰好相同时差为 0 怎么处理（丢弃、计入还是拆分）；α；区间水平；
    信息增益的蒙特卡洛样本数；没做完的运行怎么处理。
- [ ] **图谱预测效度怎么算"对上了"。** 分析会同时给出"真实正确率的点估计是否落在图谱区间内"和
  "图谱的点估计是否落在真实正确率的区间内"。每对条件只有几次运行时，两种判法的结果可能差很多，用哪一种由你在计划里写明。
- [ ] **单摆要不要加做"留出孪生的推荐"。** 已批准的计划写的是单摆每次做三项：产品里模型建议的那项、留出单摆引擎的推荐、
  一次重复；工具包默认每个实验都做"信息增益推荐、最佳固定测量、简单重复"，单摆可以用 `--twin-eig` 再加一项。
  要不要加、模型建议那一项怎么记录，由你决定。
- [ ] **单摆走"其他实验"通道时，斜率当未知还是已知。**
  - 在哪里：`catalog.py` 里单摆的配置 `slope_known`。
  - 要考虑：当未知时（产品默认的做法），整体按比例变大或变小的故障（例如每次都从同样的大角度释放、数错次数）
    会被斜率吸收，通道看不出来，在分析里按"等价于只有随机误差"计；当已知（g 当作已知）时能看出来，但这就不再是"测 g"。
- [ ] **真实弹簧能不能挂 350 g。** 工具包默认不做"再挂一组 350 g"这项追加测量，只有你确认弹簧的最大允许负载 ≥ 350 g
  时才用 `--config hooke.max_load_g=350` 解锁。
- [ ] **两项附加测量**（设计 §5.11）：学校弹簧秤竖放和横放的零点偏移（几把、每把几次），以及"修正后复测"做几次。
  工具包目前没有这两项的记录表，需要时告诉开发者。
